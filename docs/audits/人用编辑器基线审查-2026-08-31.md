# 人用编辑器基线审查（2026-08-31）

## 结论

当前项目的问题不是缺少单个功能，而是编辑操作没有稳定的端到端边界。时间轴、播放器和参数面板已经尝试接入命令事务、预览态和刷新锁，但它们仍建立在多处可变状态、索引定位和全量刷新之上。继续在现有路径上逐点修复，会持续引入跨工具回归。

本阶段目标是先做稳定的人用精剪编辑器。AI 后续只能调用同一套编辑命令，不能拥有另一套修改草稿的路径。

## 审查范围与证据

- 当前实现：`main.py`、`store.js`、`renderer.js`、`工作台v0.8时间轴.html` 与 `property/`。
- 对照实现：本地 OpenCut 源码的 `timeline/placement`、`timeline/update-pipeline`、`timeline/controllers`、`preview/controllers`、`selection` 与 `commands`。
- 运行证据：`audit_log.jsonl` 和本次真机故障后写成空工程的 `draft_state.json`。

此前文档仅作为历史线索。凡是声称“已修复”但未通过真实手势和回归测试的内容，均视为未验收。

## 必须成立的编辑器不变量

1. 除“新建工程、导入替换工程、明确删除素材或片段”外，任何命令不得让素材箱或片段数量意外归零。
2. 所有片段操作以 `segmentId` 为目标；`轨道:索引` 仅可用于当前渲染，不能作为命令的事实目标。
3. 画布、时间轴和参数面板读取同一份“播放头时刻的生效片段值”。
4. 一次手势只有三种结局：未超过阈值而成为点击、一次原子提交、一次完整取消。不得存在“画面已变但文档未变”的第四种状态。
5. 所有领域写入必须经同一命令边界，并产生可撤销、可审计、可验证的变更记录。
6. 预览刷新只能消费已提交文档或当前手势的临时预览，不能用旧响应覆盖新操作。

## 当前缺口

| 优先级 | 缺口 | 当前证据 | 用户影响 | 重构目标 |
| --- | --- | --- | --- | --- |
| P0 | 写入边界不完整 | `main.py` 存在大量 `save_state` 调用；本次空草稿写入没有对应审计命令 | 非删除操作可能清空素材和时间轴，且无法可靠追责或回滚 | 所有草稿变更统一从 Document Command 执行；持久化层拒绝未标记的破坏性写入 |
| P0 | 选择依赖索引 | 前端仍保存 `selectedKey = type:track:index`，批量删除和分组移动直接枚举这些 key | 分割、移动、建轨后选中目标漂移，可误删多个片段 | 选择状态改为 `selectedSegmentIds`；渲染时再映射轨道位置 |
| P0 | 画布提交与预览生命周期分离 | `preview-drag.js` 直接修改元素样式，松手后异步事务落库，随后清 overlay/补刷 | 关键帧拖拽弹回、拖出画布才偶发成功、面板和播放器瞬间不一致 | 一个显式 `PreviewInteractionController` 管理 pending/dragging/commit/cancel；提交成功前保留临时预览 |
| P0 | 刷新靠多把局部锁 | `refresh()` 需要分别识别 InteractionManager、关键帧拖拽、输入框和文字编辑状态 | 新工具容易遗漏锁，旧响应或轮询可以覆盖进行中的操作 | 一个 RefreshGate，带文档版本与手势 token；只允许安全时合并刷新 |
| P1 | 拖放规则混杂 | 单个 HTML 文件同时处理 hover、DOM 命中、缓存、方向、轨道创建、后端调用和滚动 | 高亮、预览影子与最终落点可能不同，素材有时“拖不进去” | 抽取纯 `resolvePlacement`，drop 事件只提交其返回的不可变 placement |
| P1 | 主轨语义不清晰 | 数据模型有 `main` 和 overlay video，拖放层又按显示索引判断 | 用户看到两条近似主轨，编辑叙事不明确 | 一条唯一 Main Track；视频覆盖轨只属于 overlay，并有明确插入/删除策略 |
| P1 | 更新规则分散 | 裁切、变速、分割、关键帧、面板修改分散在前后端多个函数 | 修时间操作会影响变换或关键帧，难以证明无回归 | 一个纯 `applyElementUpdate` 管线：派生规则和约束规则统一执行 |
| P1 | 回归测试缺少真实工作流 | 现有测试多数验证单函数或局部修复 | 每个补丁可通过局部测试但真实剪辑仍出错 | 增加端到端手势流程和草稿不变量测试 |

## 与 OpenCut 的可借鉴边界

OpenCut 的价值不是界面皮肤，而是把规则拆开并保持单向流动：

- `placement/` 以轨道快照、时间跨度和策略计算唯一落点；主轨规则独立。
- `DragDropController` 只维护拖放状态，落点由纯函数提供。
- `PreviewInteractionController` 用 `idle / pending / dragging` 状态机，预览通过 `previewElements()` 管理，松手只做 `commitPreview()`，取消只做 `discardPreview()`。
- `update-pipeline.ts` 将“修改字段”与“必须随之发生的约束”集中，例如时长改变必然裁剪动画。
- `commands/` 是文档变更的唯一入口；选择以稳定元素 ID 表示。

可以按 MIT 许可证保留声明后参考或复用其中的纯算法。不得直接搬运 React 组件到当前原生 JS/Python 架构；应先定义本项目的接口，再重实现相同行为。

## 人用编辑器 V1 验收范围

以下流程必须稳定后，才进入 AI 操作和复杂效果：

1. 导入素材，拖入唯一主轨、拖入覆盖轨和音轨；预览落点与最终位置一致。
2. 单选、多选、框选、删除、撤销、重做；任何非删除操作不得改变素材箱数量。
3. 时间轴移动、裁切、分割、跨轨移动；段 ID、源裁切、变换和关键帧保持正确。
4. 播放头在任意片段时，画布、参数面板和时间轴关键帧标记显示同一生效值。
5. 对位置、缩放和旋转的画布拖拽：预览跟手，松手一次提交，Esc/取消不落库。
6. 有关键帧时执行第 5 项：按明确产品规则更新当前时刻关键帧或拒绝编辑，不能弹回或半提交。
7. 保存、重新打开、撤销后，草稿结构和片段/素材数量可验证且一致。

## 重构顺序

### 阶段 A：先建立安全网

1. 定义 `EditorDocument`、`SegmentId`、`TrackId`、`CommandResult` 的最小契约。
2. 给 `save_state` 加命令来源和文档不变量校验；每次写盘都记录前后摘要（素材数、轨道数、段 ID 集合差异）。
3. 自动保留滚动快照；破坏性操作需要明确 command kind。
4. 增加“非删除命令不能意外清空”回归测试。

### 阶段 B：时间轴事实层

1. 将选择迁移到 ID；消灭由 index key 直接驱动的删除、移动、分组和属性写入。
2. 定义唯一 Main Track 和 overlay/audio 轨道排序。
3. 抽取 placement 纯函数，并用单元测试覆盖占用、空轨、不兼容轨、间隙、边界和多选组移动。
4. 时间轴 DOM 只渲染 placement 结果，不再重新计算业务规则。

### 阶段 C：预览与属性统一

1. 将画布拖拽、缩放、旋转和参数输入接到同一种 preview transaction。
2. 用同一生效值解析器供 renderer、属性面板和关键帧轨道读取。
3. 刷新改为带手势 token 的门控；提交确认或取消后才移除临时预览。

### 阶段 D：可验证的人用编辑器

1. 建立上述 V1 流程的自动测试与真机验收清单。
2. 只在这些流程稳定后，恢复特效、遮罩、导出和 AI 初剪的迭代。

## 明确延后项

- AI 自动剪辑、MCP 批量操作和 Agent 协作。
- 复杂效果、遮罩和高级动画编辑器。
- MP4 渲染器与剪映草稿导出扩展。

这些功能仍可保留现状，但不得继续把新写入路径接到旧的旁路逻辑中。
