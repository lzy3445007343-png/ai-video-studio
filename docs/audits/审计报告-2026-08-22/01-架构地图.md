## 一、系统总览（进程模型 + 数据流拓扑）

### 1.1 进程模型（三个进程 + 一个文件共享总线）

```
┌─────────────────────────────┐    ┌─────────────────────────────┐
│ 桌面窗口进程（main.py）        │    │ MCP stdio 进程（mcp_server.py）│
│  - PyWebView WebView2 窗口    │    │  - 由 WorkBuddy mcp.json 拉起 │
│  - localhost:8080 HTTP 媒体服 │    │  - 复用 main.Api 同构能力     │
│  - js_api=Api 实例（单例）     │    │  - 每工具调用 new Api()       │
│  - 内存 CommandManager（类级） │    │  - 内存 CommandManager（类级） │
└──────────────┬──────────────┘    └──────────────┬──────────────┘
               │  0.5s 轮询 get_state               │  写 draft_state.json
               ▼                                   ▼
        ┌─────────────────────────────────────────────┐
        │          draft_state.json（共享文件总线）        │
        │  materials[] + draft{} + version + meta       │
        │  写时 portalocker 文件锁（_HAS_LOCK）           │
        └─────────────────────────────────────────────┘
```

**事实（有源码证据）：**
- 前端 → 后端：`window.pywebview.api.<方法>()`，桥接函数 `call(method, ...args)`（store.js:135-139）。
- 后端 → 前端：**没有事件推送通道**，只有文件被轮询。前端每 500ms 调 `get_state`（工作台v0.8时间轴.html:3362-3367）。
- 两个进程**不共享内存**。`Api.cmd_mgr` 是类级属性（main.py:2432），但 MCP 是独立进程，各自实例化自己的 CommandManager。main.py 注释声称"桌面窗口与 MCP 进程共用同一份历史"（main.py:908），**该论断不成立**——撤销历史是进程隔离的（见 Phase 3 §5.4）。
- `save_state` 用 `portalocker` 加文件锁防双进程互踩（main.py:1063-1066）。

## 三、核心调用链追踪

### 调用链 ① 创建工程：素材入库 → 时间轴进轨

**前端素材双击/拖入路径：**

```
用户双击素材卡（HTML:1066） 或 拖拽到时间轴（HTML:2486-2489）
  └ call("add_to_timeline", name, path, type, track_index, playheadUs)
       └ [pywebview 桥] → Api.add_to_timeline（main.py:2525）
            └ try → self._add_to_timeline_impl（main.py:2545）
                 ├ self._reload()（2499 行：重读文件→_ensure_seg_ids→_ensure_seg_speeds→_ensure_seg_animations→_ensure_seg_src_full）
                 ├ 路径存在性校验（2550）
                 ├ _push_undo()（2468：no-op 占位）
                 ├ TYPE_TRACK[mtype] 决定轨道类型
                 ├ 定位轨道：track_tid > track_index(-1=新建) > insert_index > 默认轨（2556）
                 ├ 新建段 dict {id, name, path, type, start, duration, src_start, src_end, src_full, speed, ...}
                 ├ 同轨重叠自动避让 _free_start_on_track（347）
                 └ save_state(self.state)（1040）
                      ├ 若草稿相对 Api.last_committed 变化 → push_snapshot（5a 兜底，压"自动快照"）
                      ├ _ensure_track_tids + version = int(time.time()*1000)
                      └ portalocker 加锁写盘 + 读回校验
  └ 前端 refresh()（HTML:3218）→ get_state → renderAll（HTML:3262）
```

**事实：**
- 该链路前端**不走 execute()**，历史靠 save_state 的 5a 兜底压快照（cmd_id="snapshot"，无语义）。
- MCP 的 add_to_timeline 走 `_exec("add_to_timeline")` → `Api.execute`（main.py:2477）→ 语义 Command。
- 同一条命令，两种历史记录方式并存（见 Phase 3）。

### 调用链 ② 编辑视频：移动素材

```
用户在时间轴拖段（HTML:2225 onTimelineDown → 2236-2240 startPointer("move")）
  ├ pointermove：Store.state.drag 临时态 → renderTimeline 跟手（纯前端预览，不落库）
  └ pointerup（HTML:2058-2067）：
      ├ 跨轨：call("relocate_segment", type, ti, idx, targetTi, curLeftUs, insertIndex, segId, trackTidOf(...))
      └ 同轨：call("move_segment", type, ti, idx, round(curLeftUs), rippleOn, segId)
           └ Api.move_segment（main.py:3410）
                ├ self._reload()
                ├ 定位段：track_tid → _track_by_tid；segid → _seg_by_id；否则 (type,ti,idx)
                ├ new_start = max(0, new_start_us)
                ├ 重叠自动避让 _free_start_on_track（3464）
                ├ seg["start"] = new_start（直改状态）
                ├ ripple → compute_ripple_adjustments(before, draft) → apply_ripple_adjustments
                └ save_state(self.state) → 压快照 → 写盘

```

**事实：**
- 位置引用优先：`index` 默认语义是"该轨第几个段"；只有前端显式传 `segId` 才用稳定 id。前端拖动是传了 segId 的（A 方案）。
- 落盘后**没有增量回传**，前端靠整份 get_state 全量刷新（D2/D6）。

```json
  "material_id": "materials[].uid"（新数据）,
  "volume", "muted", "hidden",
  "animations": { "transform.positionX": {"keys": [{"id","t"(µs 段内局部),"v","seg":"linear|hold"}]} },
  "params": { "transform.positionX": v, ... }（C1 新静态层，与旧字段 mirror）,
  "transform": {"x","y","scaleX","scaleY","rotation","opacity"}（旧字段）,
  "masks": [{"id","type","params","inverted"}],
  "source_audio_extracted": bool（提取原声标记）,
}
```

**关键事实：**
- 存在**三条属性承载路径并存**：`seg.params[path]`（C1 新层）、`seg.animations[path]`（KF 通道）、`seg.volume/speed/transform.*`（legacy 字段）。property-kernel.js 的 LEGACY_MIRROR 做"params → 旧字段"单向镜像，playback-graph.js / 导出端仍主要读旧字段（`getProperty(seg, "audio.volume")` 存在时走 kernel，否则读 `seg.volume`）。
- 时间轴位置全部用**微秒**（start/duration/src_*/KF t），前端播放头 playheadUs 微秒；`version` 用毫秒；AudioContext 用秒（`/1e6` 换算）。

### 5.2 绕过 Command 的路径

1. **前端直连 API（最普遍）**：`call("move_segment")` 等直接调用 Api 方法 → 绕过 `Api.execute`/`CommandManager.execute` → 无 cmd_id 语义、无 meta 审计（audit_log 里全是 cmd_id="snapshot" 的"自动快照"）。
2. **Frontend 直改本地状态**：拖拽过程直接改 `Store.state.drag`/`OverlayState`（interaction-kernel.js:18-32，preview-drag.js:60-68）→ 本地临时态不进后端（这是设计意图，不是债；但 OverlayState 不设上限、不清理检查）。
3. **renderAll 全量重建**：每次 refresh() 显式 `renderAll(Store.state)`（HTML:3262）——不是订阅驱动，而是轮询驱动的无条件全量重绘（D6 债）。
4. **copy_buffer 直读进程内存**：Api.copy_buffer（main.py:2436）是进程内存剪贴板，跨进程不共享（MCP 进程 copy 桌面进程 paste 读不到）。

### 5.3 Undo 闭环审计（execute → history → undo → restore）

**execute 路径闭环正常：**
```
Api.execute → CommandManager.execute（main.py:927）
  cmd.saved_state = deepcopy(api.draft)   # 操作前快照
  fn() → save_state 内部 push_snapshot
  if len(history) > before: history.pop() # 弹掉 5a 快照
  history.append(cmd)                     # 语义 Command
undo：pop → api.draft = deepcopy(saved_state) → save_state(record=False) → redo_stack.append
redo：pop redo_stack → 恢复 post_state
```

**发现的闭环缺陷：**

- **P3-1 多快照残留**：`CommandManager.execute` 只弹 1 个快照（main.py:948-949）。实测 3 个方法内部调 2 次 `save_state(self.state)`：`toggle_source_audio`、`add_bookmark`、`toggle_bookmark`（按方法统计 main.py 内 save_state 计数）。这些操作经 execute 执行时会压 2 条快照、只弹 1 条 → history 残留 1 条"自动快照"，undo 一次只回一半，再 undo 一次才完全回退（undo 语义漂移）。
- **P3-2 undo 无 "saved_state == post_state" 幂等保护**：undo 直接整份深拷贝覆盖 draft（main.py:1015-1016），不比较是否真的变化；空操作也会入 redo 栈。
- **P3-3 跨进程 undo 覆盖风险**：桌面 undo 恢复的是桌面历史里保存的全量快照；若 MCP 在桌面操作之后改过草稿，桌面 undo 会把整份草稿回退到 MCP 改动之前 → **MCP 的改动被一次撤销抹掉**（无 actor 隔离的 undo）。
- **P3-4 事务 abort 不回滚 history 内已提交部分**：abort_transaction 只恢复 begin 前快照（main.py:997-1002），但 begin 之前的历史步不受影响，符合设计；不过事务内若混合了 execute 与直接 call，直接 call 的 save_state 也会压快照进入 history（事务外），导致事务边界被污染（事务内直接调 API 的路径存在，如 HTML 拖拽内部对 mask 的更新）。

### 5.4 Command 系统的"类级共享"论断不成立

main.py:908 注释："类级共享（桌面窗口与 MCP 进程共用同一份历史）"。
**事实：MCP 是独立 OS 进程（mcp_server.py，stdio），内存不共享。** `Api.cmd_mgr` 每个进程各一份。结果是：
- MCP 进程内每条 `_exec` 新建 `main.Api()`（mcp_server.py:35），`Api.cmd_mgr is None` 时新建 CommandManager → MCP 进程有自己一套 undo 历史。
- 桌面进程 undo 只能回退桌面进程内发生的操作。
- `audit_log`（main.py:1034）也只能看到本进程历史。
- 该"共享"只在**单进程**内（多次 new Api）成立，跨进程不成立。
