# 02 数据流分析报告 —— ai-video-studio

- 审计范围：Phase 2（Document / 数据模型 / 单一事实来源 / ID 体系）+ Phase 6（核心对象生命周期 / 数据流健康）
- 审计日期：2026-08-22
- 审计对象：`main.py`（后端主程序）、`工作台v0.8时间轴.html` + 27 个 JS 模块（store/media/player/playback-graph/audio-engine/timeline/effects/renderer + property/*）、`mcp_server.py`、`draft_state.json`、`effects.json`

## 1. 结论先行

1. **系统没有真正的 "Document"**。工程数据是散落在 `draft_state.json` 里的普通 JSON dict（`materials + draft`），无 Document 类、无序列化协议、无版本化 schema（`version` 只是毫秒时间戳）。撤销 = 内存深拷贝快照栈，不是可还原的文档操作日志。`property/DraftStore.js` 名不副实——它实现的是 `PropertyDraft`（单字段两阶段编辑：input→preview / blur→commit），与 "工程文档存储" 毫无关系（`property/DraftStore.js:10-57`）。
2. **每一份核心数据都存在 ≥3 份物理拷贝**（磁盘 JSON / 后端进程内存 / 前端 Store / 前端派生缓存 / 撤销栈快照），靠「每次操作前 `_reload()` 重读文件 + 前端 500ms 轮询」强行对齐。文件即总线，内存即缓存——这是架构层不一致的根源。
3. **ID 体系是"半稳定"**：段有稳定 `id`、轨有稳定 `tid`，但大量命令（关键帧 CRUD、遮罩 CRUD、特效 CRUD、轨 meta、特效 clip 绑定、前端选中 key）仍全部或部分使用位置引用 `(type, ti, index)`，`ti` 会在折叠/新建轨后漂移，导致**打点/改遮罩/绑特效可能命中错段**。
4. **数据转换错误集中在变速（speed≠1）与源窗口（src_start/src_end）**：前端播放换算与 `(src_end - src_start)/speed == duration` 不变量自相矛盾；`src_end` 是一个"所有读者都不信任、但仍有多个写者"的冗余字段。
5. **Property Kernel 宣称 `seg.params[path]` 是唯一真相源，实际被持久化/导出消费的却是 legacy 镜像字段**（`seg.transform/speed/volume`），`params` 层在前端刷新后即丢失——"唯一真相源"的架构声明与落地代码不符。

### 2.4 与理想 Document 的差距

| 维度 | 现状 | 理想 Document | 差距 |
|---|---|---|---|
| 单一对象 | 无；JSON dict 散落 | 单一 `Document` 对象，可序列化/反序列化 | 无类型边界，字段拼写全靠约定 |
| 撤销 | 内存深拷贝快照栈（CommandManager，main.py:907） | 文档级 undo/redo 事务 | 快照 O(N) 全量复制，无增量；跨进程 undo 栈不同步 |
| 引用 | 位置 + id 混合 | 全稳定 id 引用 | 见第 4 节 |
| 版本 | `version` 时间戳 | schema 版本号 + 迁移脚本 | 旧结构靠 `_migrate_old_to_x` 静默迁移（main.py:724），无显式 schema |
| 校验 | load_state 里逐字段 setdefault（main.py:830-873） | 序列化时 schema 校验 | 非法数据静默补默认值，脏字段（如 src_end）靠读者推导绕过 |

## 4. ID 体系审计

### 4.1 已有的稳定 ID

| 实体 | 字段 | 使用处 | 证据 |
|---|---|---|---|
| 段 | `seg.id`（uuid） | `segById`（timeline.js:143）、`_seg_by_id`（main.py:638）、`selectedSegId`、拖动/移动/裁剪 `segid` 参数 | `timeline.js:143-156`；`main.py:638-659` |
| 轨 | `tr.tid`/`main.tid`/`audio[].tid` | `trackTidOf`（timeline.js:335）、`_track_by_tid`（main.py:408）、`relocate_segment` 的 `to_track_tid` | `main.py:387-429`；`timeline.js:335-338` |
| 关键帧 | `k.id`（段内） | KF marker、`update_keyframe` 的 `keyframe_id` | `main.py:3009-3047` |

### 4.2 仍在使用位置引用的地方（不稳定引用，具体例子）

1. **关键帧 CRUD 全部位置寻址**：`add_keyframe/update_keyframe/remove_keyframe/clear_keyframes/get_keyframes(track_type, track_index, index, ...)`——签名里**没有 `segid`**（`main.py:2936/3009/3049/3069/3076`）。前端 `kfSegArgs()` 也传 `(type, ti, idx)`（HTML:1527-1532）。若在 500ms 轮询窗口内、后端 `_reload()` 后发现 `ti/index` 已因另一进程操作漂移，**关键帧会打到错误段上**。同类：`set_mask/update_mask_param/update_mask`（`main.py:3691-3754`）、`update_effect/remove_effect/duplicate_effect`（`main.py:4282-4334`）、`set_track_meta`（`main.py:4465`）。
2. **前端选中态双轨**：`selectedKey="type:ti:idx"`（位置）+ `selectedSegId`（稳定）。`selectedSeg()` 优先 id、回退位置（HTML:1713-1720）；但 `refresh()` 校验选中存续时位置分支用 `draftSegs(type,ti)[idx]`（HTML:3246-3250），`findSegByKey` 也是纯位置（HTML:1707-1712）。折叠/新建轨后 `selectedKey` 会指向错误的段，仅靠 `selectedSegId` 的优先校验兜底。
3. **特效 clip 绑定是位置引用**：`target={type:"clip", track, ti, si}`（`main.py:4252-4253`），前端计算作用层时用 `"video:" + t.track + ":" + t.si` 反查 layer（`effects.js:100-105`）。目标段被移动/删除后绑定静默失效或绑到错段——**没有 id，AI 无法稳定引用"我给这个片段加的特效"**。
4. **播放器轨级 key 是位置引用**：`previewState` 以 `"video:ti"` 为 key（media.js:10-15），`resolveHits` 的 key 是 `"type:ti:idx"`（player.js:50-67）。同轨段删除后 idx 变化，跨段签名 `lastHitSig`（player.js:663-667）会触发不必要的重建/暂停。

### 4.3 结论

ID 体系处于"A 方案"迁移中间态：写路径（move/trim/relocate/add）已支持 `segid`/`tid`，但**读路径和 KF/遮罩/特效路径仍是位置引用**。AI/Agent 经 MCP 用 `(track_type, track_index, index)` 调用（mcp_server.py:86-122 等），在并发/折叠场景下**引用不稳定**。

## 6. 发现的问题清单

> 风险等级：🔴 高（数据丢失/损坏/导出错）、🟠 中（错位/不一致）、🟡 低（隐患/不一致风险）

### P1 🔴 delete_material 引用检查遍历旧结构 → 误删仍被引用的素材文件
- 证据：`main.py:5114-5153`，referenced 检查 `for t in ("video","audio","text"): for segs in draft.get(t) or []`——遍历的是**旧结构** `draft["video"]/["audio"]/["text"]`；当前结构是 `draft["main"]/["overlay"]/["audio"]`（main.py:791-799 定义）。main/overlay 中的段**永远查不到** → 时间轴仍引用的素材会被当"无人引用"而删除文件。
- 影响：素材文件被删 → 导出剪映时缺文件（`VideoSegment(None)` 抛异常）、预览黑屏。
- 风险：🔴

### P2 🔴 变速 ≠1 时预览播放换算自相矛盾（视频不乘 speed、音频除反）
- 证据：不变量 `(src_end - src_start)/speed == duration`（注释于 playback-graph.js:44-50）。但：
  - 视频 `PlayerManager.seek`（media.js:467-489）：`t = srcStartUs + localUs`（**未乘 speed**），且全程无 `el.playbackRate`（全项目仅 audio-engine.js:146 设过 playbackRate，见 grep）。2x 段应消耗 2×源时长，实际只播源窗口前 `duration` 秒、且以 1x 速率 → 播放内容位置与速率双错。
  - 音频 `AudioEngine.tick`（audio-engine.js:188-191）：`elapsed = (playheadSec - c.startUs) / speed`——源进度 = 时间轴进度 **÷** speed，方向与正确公式（源进度 = 时间轴进度 × speed）相反；`schedule` 的 `dur = (srcEnd-srcStart)/speed` 与 `offset` 组合后，2x 段会在段尾之前就播完，音频提前静默。
- 影响：speed≠1 的素材，预览音画与时间轴错位；导出（pyJianYingDraft 正确支持 speed）与预览不一致。
- 风险：🔴

### P3 🟠 Property Kernel 的 `params` 是"伪真相源"，持久化/导出消费的是 legacy 镜像
- 证据：`property-kernel.js:71-76` 写 `seg.params[path]` + `LEGACY_MIRROR` 镜像到 `seg.transform/speed/volume`；而后端 `update_segment_transform` 只写 `seg.transform`（main.py:2918-2922）、`_video_clip_settings` 只读 `seg.transform`（main.py:1528-1542）、`set_segment_speed` 只写 `seg.speed`（main.py:2800）。`params` 层在 refresh（`Store.set({draft})`）后即被后端数据替换消失。
- 影响：架构声明（C1 "params 是唯一真相源"，property-kernel.js:8）与实际持久化不符；任何直接读 `params` 的代码在刷新后读到 undefined，镜像逻辑 9 处散落易漏。
- 风险：🟠

### P4 🟠 关键帧/遮罩/特效命令仍纯位置寻址，AI/并发下会命中错段
- 证据：`add_keyframe`（main.py:2936）、`update_mask_param`（main.py:3731）、`update_effect`（main.py:4282）签名均无 `segid`；前端 `kfSegArgs()`（HTML:1527-1532）传 `(type,ti,idx)`。后端 `_reload()` 每次操作前重读文件（main.py:2449-2466），另一进程（MCP 常驻）插入/折叠轨道后 `ti/index` 即漂移。
- 影响：关键帧打在错误段、遮罩/特效改错对象；与 P5 叠加时用户看到的"打点消失/值乱跳"。
- 风险：🟠

### P5 🟠 前端轮询覆盖本地未提交态，仅局部冻结
- 证据：500ms 轮询 `setInterval → refresh() → Store.set({draft})`（HTML:3362-3367）；`refresh` 内仅当 `InteractionManager.blocksRefresh()`（HTML:3221-3224）、`_kfEditing`（HTML:3227-3229）、`_kfDragActive`（HTML:3233-3235）才跳过。但 `preview-drag.js` 拖动（OverlayState 写内存）等路径在 Refresh Lock 外，且 `mask-panel` 的 `previewMaskParam` 直接改 `s.masks[0].params`（mask-panel.js:122-127）无冻结。
- 影响：编辑中值被轮询覆盖，或反之本地改动丢失。
- 风险：🟠

### P6 🟠 MCP 细粒度读取层读的是旧 schema（且 import 路径可疑）
- 证据：`mcp_server.py:26` `import studio_read as sr`——全盘扫描仅 `tests/studio_read.py` 存在（无根目录副本，`import` 会 ModuleNotFoundError 除非运行时 cwd/路径包含 tests/）。且 `tests/studio_read.py:44-69 list_tracks` 读 `dr.get(ttype)`（`draft["video"]/["text"]` 旧 list-of-lists），对当前 `main/overlay/audio` 结构返回空。
- 影响：AI 的 list_tracks/get_track_text 读到空/错误数据；若 import 失败则 MCP 读类工具全部 500。
- 风险：🟠

### P7 🟠 `src_end` 冗余字段三处写、读者全部推导 → 字段恒脏
- 证据：写者 `main.py:2597`（add）、`3508-3509`（trim）、`3787-3799`（split）、`2804`（speed）；读者 `playback-graph.js:48-50`、`media.js:471`、`main.py:1278-1281` 全部 `deriveSrcEndUs` 推导并注释"不信任 seg.src_end"。
- 影响：一旦某路径直接读 `seg.src_end`（如旧代码/第三方）即拿到过期值；双写维护成本高，属"等待出 bug"的结构。
- 风险：🟠

### P8 🟠 特效 clip 绑定 target 用位置引用（track/ti/si），无 id
- 证据：`main.py:4252-4253`（add_effect 校验）；`effects.js:100-105` 用 `"video:"+t.track+":"+t.si` 反查 layer。目标段移动后绑定失效/错位，AI 无法稳定表达"给这个片段加特效"。
- 风险：🟠

### P9 🟡 同一时间轴→播放映射存在三套实现（resolveHits / JS graph / Python graph）
- 证据：`player.js:45-70`（直读 draft）、`playback-graph.js:169-227`、`main.py:1320-1368`；且 renderPreview 视频层直读 draft 不走 graph（renderer.js:110-175）。
- 影响：改一处理论上要改三处；靠对拍脚本兜底，未来任何一处漏改即音画/导出不一致。
- 风险：🟡

### P10 🟡 轨道 meta（_track_meta）与轨道数组靠 index 对齐，前端重算一遍
- 证据：`main.py:521-547`（meta 对齐 overlay index）、`main.py:585-636`（折叠同步压缩两数组）、`timeline.js:159-173`（前端 trackMeta 重新映射）。任一新代码路径绕过对齐函数直接改 overlay/audio 数组，meta 即错位（muted/hidden 挂到别的轨）。
- 风险：🟡

### P11 🟡 撤销是进程内内存快照栈，跨进程不同步
- 证据：`CommandManager` 类级单例（main.py:908 注释"桌面窗口与 MCP 进程共用"），但 MCP 是**独立进程**（mcp_server.py 每次 `main.Api()` 新建实例），类级共享只在同一进程内成立；undo 栈在窗口进程 vs MCP 进程各自独立，`undo()` 时 `_reload` 只保证草稿最新，不保证历史一致。
- 影响：AI 撤销到 A 点、用户再撤销回 B 点，两栈互相覆盖 → 用户"撤销回不去"。
- 风险：🟡

### P12 🟡 素材元数据一次性缓存（has_audio/src_full/thumbnail/peaks）不随文件变化刷新
- 证据：`has_audio` 进轨时探测一次（main.py:2625）；`src_full` 仅缺失时回填（main.py:1186-1206）；thumbnail/peaks 导入时生成后即固定（main.py:4789-4799）。同名文件被替换后缓存过期。
- 风险：🟡

## 7. 修复优先级建议（供后续系统恢复参考，不在本次审计范围）

1. **P1**：`delete_material` 引用检查改为遍历 `_iter_all_segs`（main.py:1108 已存在现成函数）。
2. **P2**：统一源窗口换算——`PlayerManager.seek` 改为 `srcStart + localUs*speed` 并设置 `el.playbackRate = speed`；`AudioEngine.tick` 的 `elapsed` 改为 `(playheadSec - startUs) * speed`；两端与 `_playback_graph`/`deriveSrcEndUs` 收敛到单一换算函数。
3. **P4/P8**：关键帧/遮罩/特效命令增加 `segid` 可选参数并优先使用（对齐 move/trim 的 A 方案），特效 target 增加 `seg_id` 引用。
4. **P6**：`studio_read.py` 迁移到根目录并改为读取 `main/overlay/audio` 结构（或直接复用 `main._playback_graph`）。
5. **P3/P7**：要么让后端真正持久化 `params`（并让导出读它），要么删除 params 层只留 legacy 单源；`src_end` 字段落盘时停止写入（仅保留推导）。
