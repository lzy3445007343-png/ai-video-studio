## 0. 一句话定位

**这不是一个剪辑软件，而是一个「AI 可调用的视频操作系统」**。剪辑界面（播放器+时间轴）只是基础设施，真正的护城河是一套 **Video DSL**（Operation Schema ↔ Timeline Schema，经 Command 桥接），让外部 Agent 能像调用 API 一样驱动视频编辑，再导出成剪映草稿 / MP4。

---

## 1. 项目定位与战略

### 1.1 双主线
- **主线①内容生意**：AI 工具信息差 → 内容 → 部署变现。最高优先级教学产品「画面思维·反推提示词」。
- **主线②AI 剪辑工作台（本项目，当前重点）**：造「AI 可调用视频操作系统」，不是做第二个剪映/CapCut。

### 1.2 编辑器官方路线（2026-08-28 拍板，覆盖旧「M 系列先行」）
- **路 C（已定）**：数据模型**不换**（保留剪映 `draft_content.json` 资产），只重做「编辑逻辑的实现方式」。
- **否决路 A**（换模型对齐 OpenCut）：剪映特效是「特效 ID + 参数」体系，翻译不过去，会自断剪映高级能力。
- **两层导出**：① 导剪映草稿（`pyJianYingDraft`，已通）② 直导 MP4（**待做，必须自研渲染器，绕不过**）。
- **垂直切片代替水平分层**：能力块从头做穿（预览 → 落库 → 导出 → 参数面板 → MCP），避免层间断层。
- **「功能做实」判定标准**：预览看得见 **且** 导出剪映草稿仍存在（双验证）。

### 1.3 架构冻结（ADR-001，2026-08-15）
- 播放器 + 时间轴 = 基础设施；Operation Schema ↔ Timeline Schema 经 **Command** 桥接；**Agent 永不直接碰 Timeline**。
- 护城河 = Video DSL，不做 Premiere/CapCut 壳。
- 冻结的是**决策**，不是代码落地——路 C 编辑逻辑（P7）落码进行中，未全收口。

### 1.4 技术栈
- 纯 **Python + PyWebView**（弃 Electron）。项目根：`Desktop/ai-video-studio/`。
- 前端：原生 JS（无框架）+ 内联脚本在 HTML 里。**改 HTML 必须重启 `start.bat` 才生效**。
- 播放器内核已抽离独立：`player.js` / `media.js` / `renderer.js`（A→D 全落地，日常正常）。
- 剪映草稿 = 文件夹 + `draft_content.json`（materials / tracks / segments），时间单位**微秒**；`seg_id`（32 位 hex 段 id）≠ `material_id`。
- MCP 机制：本地 MCP 需完全退出 WorkBuddy 重开才热加载（仅重启桌面端无效）。

### 1.5 OpenCut 参照纪律
- 参照源码在 `reference/opencut-app-src`（新版 85.4k⭐️ TS/React）；蒸馏分析在 `AI剪辑工作台-知识库/OpenCut行为层圣经` + `OpenCut编辑器圣经`。
- **只抄行为规格、用剪映数据模型重实现，不抄 OpenCut 代码**（守 ADR-001 红线）。

## 5. 给 Codex 的红线（动刀前必读，违反即破坏项目）

1. **DOM id 一个不改**（前端靠 id 绑定，改了全断）。
2. **脚本加载顺序不动**。
3. **不碰** `draft_content.json` 结构、`seg_id`、`track_type` 语义。
4. **Command API 契约不动**（Agent 经 Command 桥接，契约变了外部调用全废）。
5. **关键帧菱形标记 / 面板结构不动**；保留我们「属性名前菱形（宽度◆/X◆/Y◆/旋转◆）」语义，不抄 OpenCut 的 `isDisabled`。
6. **剪映导出 + MCP 入口不删**。
7. **不抄 OpenCut 代码**，只搬行为规格用剪映模型重实现。
8. **写库闸门**：任何写回工程文件的交互值先过合理性检查，越界整笔丢弃 + `console.warn`，绝不写坏值跨重启留存。
9. **牵连处必查**：改一个链路，grep 所有牵连处（调用点 / 对称路径 / 撤销栈 / 乐观锁 / 前端同步）评估影响再落码。
