## 三、#B-01 拖入回弹 · 全链路诊断（已读真实代码）

**落点链路**：`onTimelineDrop`(HTML:3446) → `computeDrop`(timeline.js:295) → `_enqueueAdd` → 后端 `add_to_timeline`(main.py:3636) / `_free_start_on_track`(main.py:387)。

**「回弹」= 段没落在你拖的位置**，有两个候选真因（都已定位代码）：

### 候选 1：库拖入 `verticalDragDirection=null` → 新轨永远建在上方
- `工作台v0.8时间轴.html:3501`：`computeDrop(e, wantType, **null**, atTimeUs, true)` —— 库拖入显式传 `null`。
- `timeline.js:369-373`：direction 未知→回退 `above`（`preferredDisplay i`），即**落入间隙时新轨恒建在上方轨**。
- 轴内移动(L2784)正确算了 `d.verticalDragDirection`（up/down），库拖入没算 → 你拖到两条轨**下方**间隙，却建到上方 → 视觉「错位/回弹」。
- **修复**：库拖入 `dragstart` 记录起始 Y，drop 时按 `dragstartY vs 当前 Y` 算 up/down 传给 computeDrop（替换 L3501 的 null）。

### 候选 2：后端 existing 轨落点重叠 → 右推避让
- `main.py:3711-3712`：`if any(overlap): start = _free_start_on_track(segs, start, duration)` —— 命中已有同类型轨且该位置被占时，段被**右推到最近空位**。
- 理论上 `computeDrop:324` 已在前端把「占用→新建轨」拦截，但边界/帧吸附 rounding 可能漏判 → 走到 existing 路径触发右推。
- **修复**：existing 轨重叠时**改新建同类型轨**（对齐 OpenCut `resolveTrackPlacement` 永不右推），而非 `_free_start_on_track` 右推。
