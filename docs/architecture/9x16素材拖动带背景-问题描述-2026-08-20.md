## 一、用户看到的现象（用户原话，未经转述）

> "我 9:16 的素材放到 16:9 里面，正常来说它只占一部分。"
>
> "正常来说，我应该是拖着那个 9:16 的素材到处跑，但是它后面好像又多了一个什么东西，把它给补全了，把它的背景。好像能看到哈，黑色的。"
>
> "拖着走应该是只拖着那个 9:16 的那个素材，那个长方形素材跑的，但是他那里给补全了，补到 16:9 了。我也不知道补的是背景还是什么东西。"

**现象提炼**：
1. 9:16 素材放进 16:9 画布，静止显示时素材只占画面一部分（左右有黑色区域）——**这是预期**（用户认可）
2. **拖动素材时**：素材"带着一个黑色背景"一起移动——视觉上不是只拖 9:16 素材本体，而是拖了一个被"补到 16:9"的东西
3. 用户不确定补的是"背景"还是别的，但**确定这不是期望行为**

## 二、WorkBuddy 的根因假设（⚠️ 这是推断，未真机验证，仅作排查方向）

### 假设 A：wrap 尺寸 = 画布大小，拖动移动了整个 wrap

- 我们的预览实现（renderer.js）：每条视频轨一个 **wrap（div.vis-layer）**，wrap 尺寸 = **铺满 preview-stack（画布大小，100%×100%）**，内部 video 元素也是 100%×100% + `object-fit: contain`
- 9:16 素材 → video 保持 9:16 居中，**左右黑边是 video 自带的 letterbox**
- **拖动时（preview-drag.js）：`wrap.style.transform = translate(...)` → 整个 wrap（含黑边区域）一起移动**
- 视觉结果：黑边跟着素材跑 → "素材带着黑色背景移动"、"被补到 16:9"

### 假设 B（已排除/次要）：object-fit 被拉伸

- CSS 是 `object-fit: contain`（letterbox），静态显示时素材没被横向拉伸（用户截图人物比例正常）
- 排除"素材被拉伸填满"的可能

### 假设 C（次要）：preview fit（画布适配）未做，stack 尺寸异常

- 画布比例切换（16:9 → 9:16）时 preview-stack 没有做 scale 适配（Backlog B2 曾记"stack 608×1080 超出容器被裁切"）
- 但本次现象（16:9 画布 + 9:16 素材）与 B2 的 9:16 画布裁切是**两个不同场景**，需分开看

## 三、OpenCut 源码实证（opencut-classic，已读）

### 3.1 素材 bounds = 素材真实尺寸（不是画布尺寸）

`preview/element-bounds.ts:45-50`：

```ts
const containScale = Math.min(
  canvasWidth / sourceWidth,     // 画布宽 / 素材宽
  canvasHeight / sourceHeight,   // 画布高 / 素材高
);
const scaledWidth = sourceWidth * containScale;    // 素材显示宽 = 源宽 × containScale
const scaledHeight = sourceHeight * containScale;
```

- **OpenCut 默认也是 contain（letterbox）**：9:16 素材进 16:9 画布 → containScale = 0.5625 → 素材显示为 9:16 完整居中，左右黑边。**黑边本身与我们的 `object-fit: contain` 行为一致**
- 关键差异：**OpenCut 的"素材"是一个 9:16 的真实尺寸矩形（bounds）**，不是画布大小的层

### 3.2 OpenCut 拖动 = 移动素材 bounds，画布背景不动

- 拖动改 `transform.position.x/y` → `bounds.cx = canvasWidth/2 + position.x` → 素材矩形移动
- **画布背景（黑边区域）是画布底色，不随素材移动**
- 所以 OpenCut 里拖 9:16 素材，黑边区域永远不动，只有 9:16 的素材矩形在画布上滑动

### 3.3 我们的差异（一句话）

| | OpenCut | 我们 |
|---|---|---|
| 素材尺寸 | **素材真实尺寸**（9:16 矩形） | **wrap = 画布大小**（100%×100%，video 铺满 + contain） |
| 拖动移动什么 | 素材 bounds（9:16），背景不动 | 整个 wrap（画布大小），**黑边跟着动** |

## 四、WorkBuddy 建议方向（待 GPT 评审）

**方向 1（对齐 OpenCut）**：wrap 尺寸改为**素材实际渲染尺寸**（按源素材宽高比计算，如 9:16），而不是铺满画布。
- 拖动移动 wrap（= 素材本体），黑边区域由画布底色承担、不动
- 涉及：renderer 的 wrap 尺寸逻辑 + preview-drag hit-test + transform 应用（中等改动）
- 风险：多轨层级、播放器 seek、遮罩/贴纸联动都要验证

**方向 2（最小改）**：保持 wrap 画布大小，但把"内容层"（video）从 wrap 中拆出单独移动——wrap 不动、内容动。
- 改动小但引入新的层级，与现有 applyKfTransform 结构冲突风险

**方向 3（不改）**：黑边是 letterbox 预期行为，仅向用户解释"拖动时黑边跟随"是 wrap 语义，可接受就不改。
