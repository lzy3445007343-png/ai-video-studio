## 🎯 阶段 Core：Phase Core Refactor（GPT 新路线，核心）

> **三大架构债**（GPT 定序）：P0 数据寻址统一 → P1 文档态/交互态分离 → P2 Command 事务化。**订阅切片排最后**。

### C1 · Property Kernel（数据寻址统一 —— 一切的地基）
> **v2（GPT 评审）**：核心=唯一属性访问协议（Property Access Protocol），params 是承载层非核心；registry 提升为协议层（path→定义，未来 Agent/MCP 只认 path）；双写改**单向 params→legacy mirror**；**C1.4（KF 读取合一）延后到 C2**；不加 set_property 后端命令。方案见 docs/architecture/C1-property-kernel-方案-2026-08-20.md
- **目标**：所有属性统一 path 寻址——静态值在 `params[path]`、动画在 `animations[path]`、读取走 `PropertyResolver`
  ```js
  resolveProperty(seg, "transform.positionX", playheadUs)
  // 内部：有 animation → kfVal；无 → params 静态值
  ```
- **params 注册表**（含 keyframable/min/max/step）——一表驱动 UI/插值/曲线（参考 OpenCut params/registry.ts）
- **Strangler**：旧字段 `seg.transform.x` / `seg.volume` / `seg.speed` 用 adapter 映射到 params，**不推倒不重写**
- **不改 UI**；renderer/KF/面板的读取逐步换成 resolveProperty
- ✅ 验收：面板改值/预览拖动读同一数据源，A1 弹回消失；KF 保持原样（C1.4 延后 C2）

### C2 · Interaction Kernel（文档态/交互态分离）
- **GestureSession 状态机**：idle → prepare → dragging → commit（不再只是零散事件）
  - 未来缩放/旋转/框选/多选都复用同一状态机，preview-drag 移入
- **OverlayState**：拖动中间态存 overlay（不碰正式数据），渲染读 overlay 叠加
- ✅ 验收：拖动/缩放手柄/旋转走同一 GestureSession

### C3 · Command Transaction（Command 事务化）
- **beginTransaction() / commitTransaction()**：一次拖动（可能改 x/y/scale/rotation 多个）= **一条 undo**
- 前端所有写操作统一封装（Agent/MCP 复用同一入口）
- 顺带查 A2 undo 快照污染
- ✅ 验收：一次拖动=一条 undo；A2 全空消失
