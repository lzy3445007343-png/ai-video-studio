## 1. FableCut 时间轴/播放器深挖结论（源码实证）

### 1.1 轨道结构：固定 7 轨，无画中画概念（靠叠层）
- `TRACKS = [V3, V2, V1(视频) + A1..A4(音频)]`，固定 7 轨，`MAX_AUDIO_TRACKS = 16`，轨道高度/配色固定。
- **无显式画中画（PiP）功能**——靠 V2/V3 叠层 + `cornerRadius`（圆角）实现"PiP look"。视频放 V2 缩小 + 圆角 + 边框 = 画中画。
- 对照我们：`draft.video` / `draft.audio` 是**动态数组（轨道数不限）**——更灵活但 UI 复杂（我们 UI"乱"的根源之一）。**画中画我们天然支持**（多轨 + transform 缩放），需验证。

### 1.2 播放协调：single source，与我们 MasterClock 同构
```js
function syncMedia() {              // loop(RAF) 每帧调用
  const t = state.time;             // 单一时间源
  for (clip of clips) {
    const mt = mediaTimeAt(c, t);   // 时间轴 t → 源时间
    if (playing && activeAt(c,t)) { el.play(); 变速; |el.currentTime-mt|>0.25*eff 才 seek }
    else el.pause();                // 非激活停车
  }
}
```
- `state.time`（秒）= 我们的播放头（us）；`mediaTimeAt` = 我们的 PlayerManager.seek 换算；drift 校正 = 我们的 correctActiveMediaDrift；非激活停车 = 我们的 inactive-park。**架构同构**。
- 时间轴 playhead 跟随 `state.time`（`els.playhead.style.left = state.time * pps`）——**时间轴与播放器从同一时间派生，天然"走到哪播到哪"**。

### 1.3 它的软肋（诚实分析）
1. **每帧 O(n) 扫全部 clip + canvas 全量重绘**（drawFrame 每帧 drawImage 所有可视 clip）——clip 多/分辨率高会卡。我们增量（同段不 seek，keySig 才跨段），更省。
2. **el.currentTime 强制校正无 WebView2 兼容层**——它在普通 Chrome 测的；换 WebView2 会踩我们已根治的"吞 seek/管线重置"坑。**我们环境更难，这仗我们赢了**。
3. 固定 7 轨（V3 还偏矮）——叠层能力有限（我们多轨自由）。

### 1.4 用户体验评价（真机）
界面干净舒服（布局/配色专业）✅ / 时间轴↔播放器无卡顿 ✅ / MP4 拖入自动分离音频（linkGroup）✅ / 调色+滤镜 ✅ / 字幕动画 12 种 ✅ / 轨道固定有限 / 无独立 PiP（叠层代替）。

## 2. 特效两路线（用户拍板）

| 路线 | 播放器预览 | 导出 | 目标 |
|------|-----------|------|------|
| A. 播放器简单特效 | 自实现（CSS/JS 原语） | 两端可表达→映射剪映；否则降级 | 预览所见即所得 |
| B. 剪映草稿承接 | 显示"预览不支持"占位 | 保留剪映特效字段，剪映里正常渲染 | 沾剪映的光，不重复造轮子 |

**原则**（前夜已定）：播放器 ≠ 剪映，特效走三层对策（两端可表达 / 自建原语 / 剪映独有占位）。**前期以 B 为主（导出剪映草稿），A 只做基础 transform/filter**。
