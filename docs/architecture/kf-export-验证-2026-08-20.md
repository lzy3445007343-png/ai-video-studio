## 2. ⚠️ 新缺口：静态 transform 导出缺失（B5 暴露，登记待修）

**现象**：`export_draft` 里视频/图片段（main 轨 + overlay video 轨，同一循环 main.py:4549-4574）创建 `VideoSegment` 时**只传了 source_timerange/volume/speed，没有传 clip_settings**。用户拖了素材位置/改缩放（静态 transform，`seg.transform`）但**没打 KF** → 导出剪映后**位置/缩放/旋转全部丢失**（素材回到画布中心原始大小）。

**对照**：
- 贴纸轨（main.py:4515/4534）用了 `_seg_clip_settings` ✅
- 视频轨 ❌ 未传 clip_settings
- **只有打了 KF 的属性才通过 `_apply_keyframes_to_segment` 导出**（KF 值 = 剪辑时刻的值，剪映里 KF 生效但 base 缺失）

**修复方向（不阻塞 B5 KF 验证，第二阶段或独立任务）**：
1. 新增 `_video_clip_settings(seg, W, H)`：`seg.transform`（{x,y,scaleX,scaleY,rotation,opacity} px 语义）→ ClipSettings：
   - transform_x = x/(W/2)、transform_y = -y/(H/2)（与 KF 换算同源，复用 half_w/half_h）
   - scaleX/scaleY/rotation/opacity 直传
2. **必须先解决 scale 的 contain 语义**：前端预览 scale=1 = 素材 contain 到画布（R1 Element Bounds）；剪映 scale=1 = 原始分辨率。直接传 1.0 会让 1920x1080 素材在 1080x608 画布超界。需要像贴纸的 STICKER_BASE_HEIGHT_RATIO 一样，定义视频的"scale=1 对应画布占比"（或按素材 natural 尺寸 × contain 系数换算）。
3. 优先级：**低于 B3 菱形拖拽**（当前视频轨导出在无 KF 时本来就丢位置，属历史行为；KF 是新增能力，已验证正确）。建议 B5 真机验收后列为独立修复项。
