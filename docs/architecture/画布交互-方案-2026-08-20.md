## 1. 目标与范围

**组 1：画布缩放 + 平移**（viewport zoom/pan）
- Ctrl/Cmd + 滚轮 = 画布缩放（0.25x ~ 16x，指数平滑）
- 普通滚轮 / 中键拖动 = 画布平移（zoom > 1 时）
- 右下角缩放 UI：- / 100% / + / 适应屏幕 / 实际大小 / 滑块（%显示）
- 双击适应？可选

**组 2：素材缩放手柄 + 旋转手柄**（transform handles）
- 选中素材 → 4 角 + 4 边手柄（拖动改 scaleX/scaleY，shift 锁定比例，alt 以中心缩放）
- 顶部旋转手柄（拖动改 rotation）
- 复用 InteractionManager + GestureSession（ResizeSession / RotateSession）

## 2. OpenCut 模型（源码实证）

### 2.1 Viewport Geometry（preview-coords.ts 全文件）

```ts
interface PreviewViewportGeometry {
  canvasWidth, canvasHeight,        // 画布逻辑尺寸（1080×608 等）
  centerX, centerY,                 // 画布中心（逻辑坐标，平移时变）
  scale,                            // 显示缩放 = fitScale × zoom
  viewportWidth, viewportHeight,    // 预览容器实际尺寸
}
// canvas 原点（屏幕坐标）：
origin = { x: viewportW/2 - centerX*scale, y: viewportH/2 - centerY*scale }
// 换算：
screenToCanvas(clientX, clientY)  = { center + (screen - viewport/2)/scale }
canvasToOverlay(canvasX, canvasY) = origin + canvas*scale
positionToOverlay(positionX, positionY) = canvasToOverlay(canvasW/2 + positionX, ...)  // position 相对画布中心
```

### 2.2 Viewport State（preview-viewport.tsx:209-495）

```ts
zoom    // 用户缩放倍率，默认 1（=fit），clamp [0.25, 16]
center  // 画布中心逻辑坐标，默认 {canvasW/2, canvasH/2}
fitScale = min(viewportW/canvasW, viewportH/canvasH)
viewportScale = fitScale × zoom
// 缩放：scaleZoom(factor) → zoom *= factor (clamp)；zoomIn/Out ×/÷1.25；fitToScreen；setActualSize(1/fitScale)
// 平移：panByScreenDelta({deltaX, deltaY}) → center += delta/scale（clamp 画布边界内）
// clamp：getClampedCenterAxis——中心不能拖出画布（visibleHalfSpan=viewportSize/(2·scale)）
// canPan = zoom > 1；zoomPercent = viewportScale×100
```

### 2.3 触发方式（preview/components/index.tsx:226-286）

```ts
onWheel:
  isZoomGesture = ctrlKey || metaKey
  → Ctrl+滚轮：pendingZoomDelta += deltaY，RAF 合并，zoomFactor = exp(-delta/300) → scaleZoom
  → 普通滚轮（canPan 时）：delta → panByScreenDelta（RAF 合并）
中键拖（preview-viewport handlePanPointerDown）：button===1 && zoom>1 → PanSession(center+clientX/Y+pointerId) → move: center -= delta/scale
```

### 2.4 缩放手柄（transform-handle-controller.ts:159-300）

- 8 个手柄（4 角 + 4 边），选中素材时显示
- 角拖：scaleX/scaleY 同时变（shift 锁定比例 = 同值；alt = 以对侧为中心）
- 边拖：只改对应轴
- 算法：corner 到对侧角的距离比 → clampScaleNonZero → 新 scale
- **手柄拖 = 改静态 transform**（buildCornerScaleAnimationReset 会清动画通道——OpenCut 语义：拖手柄时若有动画则清除）

## 3. 我们现状 vs OpenCut

| 能力 | OpenCut | 我们 |
|---|---|---|
| Viewport geometry | ✅ 统一坐标系 | ❌ 固定 scale（stack.width/cp.W），无 center 概念 |
| 缩放 | ✅ zoom clamp + RAF | ❌ 无 |
| 平移 | ✅ center clamp | ❌ 无 |
| 坐标换算 | ✅ screenToCanvas/canvasToOverlay/positionToOverlay | ❌ 散落（_previewScale、rect 换算） |
| 缩放手柄 | ✅ 8 手柄 + shift/alt | ❌ 无 |
| 旋转手柄 | ✅ 顶部 | ❌ 无 |
| InteractionManager | ✅（我们有 GestureSession 状态机） | ✅ 已有，可复用 |

**我们的优势**：C2 InteractionManager + GestureSession 状态机已就位——**手柄直接 extends GestureSession**，不需要新事件模型。

## 4. 组 1 设计（画布缩放 + 平移）

### 4.1 PreviewViewport（vanilla JS，独立对象）

```js
// preview-viewport.js（新建）
const PreviewViewport = {
  zoom: 1,            // 用户缩放倍率（1=fit）
  centerX: 540, centerY: 304,   // 画布中心（逻辑坐标，随 canvas 比例重置）
  fitScale: 1,        // 适配缩放 = min(viewportW/canvasW, viewportH/canvasH)
  get scale() { return this.fitScale * this.zoom; },
  // canvas 原点（屏幕坐标）
  origin() { return { x: vw()/2 - this.centerX*this.scale, y: vh()/2 - this.centerY*this.scale }; },
  // 换算（对齐 OpenCut preview-coords）
  screenToCanvas(cx, cy) { ... },
  canvasToOverlay(cx, cy) { ... },
  positionToOverlay(px, py) { ... },   // position 相对画布中心
  // 缩放（clamp 0.25~16）
  scaleZoom(factor) { this.zoom = clamp(this.zoom*factor, 0.25, 16); this.invalidate(); },
  // 平移（clamp 画布边界内）
  panByScreenDelta(dx, dy) { center -= delta/scale; clamp; invalidate(); },
  invalidate() { /* 触发 renderAll 或定向渲染（预览相关） */ },
};
```

### 4.2 渲染迁移（Strangler：替换散落的 sc 换算）

| 现状 | 改为 |
|---|---|
| renderPreview 的 wrap 尺寸/定位（R1: left 50% + margin + translate） | **positionToOverlay(t.x, t.y) 算 wrap 中心屏幕坐标 → left/top = center - wrapSize/2** |
| applyKfTransform 的 `sc = stack.width/cp.W` | `PreviewViewport.scale`（含 zoom） |
| preview-drag 的 `_previewScale()` | `PreviewViewport.scale`；hit-test 用 overlay 坐标 |
| 遮罩/贴纸（相对 wrap） | 不动（wrap 已正确，viewport 只影响显示位置） |
| 时间轴/播放器/导出 | 完全不动（viewport 纯显示层） |

**关键**：**素材属性（transform.x/y/scaleX...）是画布逻辑坐标，不随 zoom 变**——viewport 只改"画布到屏幕"的换算。这保证：数据层（PropertyKernel）不受影响，只有渲染层换算变。

### 4.3 触发绑定

```js
// previewStack 容器 wheel（capture + passive:false）
onWheel(e):
  ctrl/metaKey → scaleZoom(exp(-deltaY/300))（RAF 合并，防抖动）
  否则 canPan（zoom>1）→ panByScreenDelta（RAF 合并）
// 中键拖：button===1 && zoom>1 → PanGesture（可用 GestureSession 或轻量 PanSession）
```

### 4.4 缩放 UI（右下角）

```
−  100%  + | 适应屏幕 实际大小 | slider(25-200%)
```
- −/+：zoomOut/zoomIn（×/÷1.25）
- 100%：setActualSize（zoom = 1/fitScale）
- 适应屏幕：fitToScreen（zoom=1, center 归中）
- slider：setViewportPercent（zoom = percent/100/fitScale）
- 显示 zoomPercent

## 6. 迁移步骤（每步独立 commit + jsdom + 真机）

```
V1  PreviewViewport 对象 + 坐标换算（纯新增，未接入渲染，行为零变化）
    → jsdom：screenToCanvas/canvasToOverlay/positionToOverlay 数学 + clamp
V2  渲染迁移：applyKfTransform / renderPreview wrap 定位 / preview-drag 换 PreviewViewport.scale
    → jsdom：zoom=1 时与现状完全一致（回归）；zoom=2 时位置换算正确
    → 真机：素材位置/拖动/播放正常（zoom=1 无感）
V3  触发绑定：Ctrl+滚轮缩放 + 滚轮/中键平移 + RAF 合并
    → 真机：Ctrl+滚轮画布缩放、滚轮平移、中键拖
V4  缩放 UI（右下角 -/+/100%/适应/滑块/%显示）
V5  组2 缩放手柄（ResizeSession + 8 手柄渲染 + shift/alt）
V6  组2 旋转手柄（RotateSession）
```

## 7. 影响面与风险

| 项 | 影响 | 风险 |
|---|---|---|
| 渲染换算（applyKfTransform/renderPreview/preview-drag） | 全部换 PreviewViewport.scale | ⚠️ **最高**：V2 必须保证 zoom=1 与现状一致（回归测试） |
| 素材属性坐标系 | 不变（画布逻辑坐标，viewport 纯显示） | 低（PropertyKernel 不受影响） |
| 遮罩/贴纸 | 不动（相对 wrap） | 低 |
| 播放器/时间轴/导出 | 不动 | 无 |
| 手柄 | 新增 overlay 层 + ResizeSession/RotateSession | 中（命中优先级：手柄 > 素材） |
| 与 R1 bounds | wrap 尺寸=素材尺寸不变，只改定位换算 | 中（V2 要把 R1 的居中逻辑并入 positionToOverlay） |
