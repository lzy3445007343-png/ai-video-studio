## 一、7 条操作链路全图

### 链路① 拖时间轴段（move/trim/换轨）

```
mousedown .seg → onTimelineDown → startPointer（HTML:1839）
  ├→ Store.set({ pendingDrag })            → 订阅 pendingDrag → renderTimeline
mousemove → onPointerMove（HTML:1902）
  ├→ pending→drag 升级：Store.set({ drag })  → 订阅 drag → renderTimeline + _emit→renderAll(①)
  ├→ 每帧：d.curLeftUs 原地改（不 set）
  │   └→ _scheduleDragRender() = Store._emit()   → renderAll（renderMedia + renderTimeline 全量重建 + renderPreviewMaybe）
  └→ ★ 每 mousemove 一次 renderAll → 每帧全量重建时间轴 DOM
mouseup → onPointerUp（HTML:1989）
  ├→ Store.set({ drag: null })              → renderTimeline
  └→ call("move_segment"/"relocate"/"move_group") .then(refresh)
      └→ refresh → get_state → Store.set({draft,...}) → _emit→renderAll(①) → 尾部 renderAll(②)【双跑】
```

### 链路② 拖 KF 菱形 marker

```
mousedown .kf-marker → onTimelineDown 拦截 → startKfMarkerDrag（HTML:2130）
  ├→ _kfDragActive = true（锁 refresh）★ 裸全局变量，无 pointercancel 兜底
  ├→ 更新 _selKf + refreshKfMarkerSelection（只改 class，不重建）
  ├→ EditContext.lockSelectedKeys + 缓存 marker DOM 引用
mousemove → move：session.deltaTicks + 纯计算改 marker.style.left（0 set / 0 emit / 0 落库）✅ 跟手
mouseup → up
  ├→ _kfDragActive = false
  ├→ 单击：seekPlayhead → Store.set({playheadUs}) → updateKfPanelValues + _emit→renderAll
  └→ 拖动：withTx → beginTx → execute(update_keyframe)×N → commitTx → refresh（同①双跑）
```

### 链路③ 拖预览素材（标杆实现 ✅）

```
pointerdown previewStack → onPreviewDragDown（preview-drag.js:146）
  ├→ selectKey（未选中则单选）
  ├→ EditContext.lockEditTime（锁定 localUs，X/Y 共用）
  └→ InteractionManager.begin("preview-transform", DragSession)
mousemove → manager.handleMove → DragSession.onPointerMove
  ├→ OverlayState.set(X/Y)（interactionDraft，不碰 seg）
  └→ 直接改 el.style（跟手）——0 set / 0 emit / 0 renderAll ✅
pointerup → manager.handleUp → commit()
  ├→ 有动画通道：withTx add_keyframe(X/Y, 锁定localUs) → refresh
  ├→ 无动画：withTx update_segment_transform → refresh
  └→ manager.end → destroy → OverlayState.clear
```

### 链路④ 面板输入改值（KF 通道）

```
focus input → _kfEditing = true + _editCtx 锁 local（KET）
input → 有KF: KfChannel.upsertLocal + renderPreview（本地打点，0 后端 call）
      → 无KF: setProperty + renderPreview
blur → _kfEditing = false → withTx（开→add_keyframe / 关→update_segment_transform）→ refresh
★ 例外：toggleKf（◆ 按钮，HTML:1672）用 TimelineMapper.playheadLocal(s) 实时读播放头——未锁！
```

### 链路⑤ 播放头拖动（性能标杆 ✅）

```
mousedown playhead/ruler → onPlayheadDown/onRulerDown
  ├→ pausePlay + _phScrub = true
  └→ Store.set({playheadUs})
mousemove → onPhMove（HTML:2387）
  └→ 直接 Store.state.playheadUs = us（不 set 不 emit）
      → positionPlayhead + renderTimecode + syncOverlayVisibility + 预览 seek 节流 80ms ✅
mouseup → onPhUp → Store.set({playheadUs}) → renderAll 一次
```

### 链路⑥ 素材库拖入时间轴

```
dragstart 素材卡 → 记录 __libDropCache
dragover timeline → showDragLine + showClipGhost（影子段预览，纯视觉）
drop → onTimelineDrop
  ├→ 库内素材 → call("add_to_timeline", ...) .then(refresh)
  └→ 外部文件 → call("drop_files"/"import_media_by_paths") → 后端 ffmpeg/ffprobe（同步！）
      → refresh（同①双跑）
```

### 链路⑦ 500ms 轮询（结构性嫌疑最大）

```
setInterval(500ms)（HTML:3353）
  └→ booted && !Store.state.drag && !isLibraryDragging
      → _suppressPanelRender = true
      → refresh()（HTML:3209）
          → call("get_state") → Store.set({draft, materials, thumbMap, waveMap, meta, bookmarks})
              → _emit → renderAll ①（renderMedia + renderTimeline 全量重建 + renderPreviewMaybe + ...）
          → 尾部显式 renderAll ②【与 ① 双跑！】
          → updateToolbarState + renderKfPanelPF（被 _suppressPanelRender 跳过）+ applyCanvasRatio
      → finally _suppressPanelRender = false
```

## 二、refresh() 调用源清单（事件触发链图）

| # | 调用源 | 频率 | 是否过锁 |
|---|---|---|---|
| 1 | 500ms 轮询 setInterval | 每 0.5s 一次 | ✅ 锁内跳过（InteractionManager/_kfEditing/_kfDragActive） |
| 2 | 所有后端写操作 .then(refresh)（move/trim/split/add/undo/redo...） | 每次动作一次 | ✅ 同上 |
| 3 | 拖段 onPointerUp 提交后 | 松手一次 | ✅ |
| 4 | boot() 初始化 | 一次 | ✅ |
| 5 | refresh 锁内被调（notePendingRefresh）→ 会话结束补刷 | 交互结束一次 | — |

**refresh 三层锁**：`InteractionManager.blocksRefresh()`（preview-drag 等 C2 会话）/ `_kfEditing`（面板输入聚焦）/ `_kfDragActive`（KF 菱形拖拽）。

## 三、渲染双通道（结构性重复）

```
Store.set(任意key) → 切片订阅者（精准）+ _emit → Store.subscribe(renderAll) → renderAll ①
refresh() 尾部 → renderAll ②（显式）
→ 每次 refresh = renderAll 跑 2 遍；renderAll 内 renderTimeline = 全量销毁重建 DOM
```

`Store.subscribe(renderAll)`（HTML:1254）与 `refresh()` 尾部 `renderAll(Store.state)`（HTML:3253）**双跑**。
`renderTimeline`（timeline.js:491）每次 `.querySelectorAll(".track,.seg").remove()` 全量销毁重建。

## 四、疑点定性（静态证据）

| # | 疑点 | 静态证据 | 定性 |
|---|---|---|---|
| A | **UI 跟手性（用户本轮点名）** | 拖段每帧 `_scheduleDragRender→_emit→renderAll→renderTimeline 全量重建`；轮询每 0.5s 全量重建 ×2。段多/素材多必卡。对比链路③⑤（直接改 style / 不 emit）才是跟手标杆 | ⚠️ **确认风险** |
| B | **renderAll 双跑** | `Store.subscribe(renderAll)` + refresh 尾部显式 renderAll | ⚠️ 确认（每次 refresh 全量 ×2） |
| C | **X/Y 错位实时产生路径** | `toggleKf`（◆ 按钮）实时读 `playheadLocal`，两次点击间播放头微动 → 不同点。KET 只锁了 input blur，**◆ 按钮未锁** | ⚠️ **高嫌疑**（需动态验证） |
| D | **KF 拖拽锁无兜底** | `_kfDragActive` 裸全局变量，mousedown 置 true 但 **pointercancel/鼠标移出窗口无释放路径** → 锁死则 refresh 永久跳过 | ⚠️ 风险（偶发"UI 不动了"候选） |
| E | **轮询全量重建** | 500ms 轮询 = get_state + renderAll（含 renderMedia/renderTimeline 重建）——无操作也持续 CPU | ⚠️ 性能隐患 |

## 五、与新版 OpenCut 对照（静态结论）

新版组织：`Editor Core + Managers`（media-manager/timeline-manager/selection）+ 显式方法调用 + **订阅式渲染（组件级复用，不重建 DOM）** + 播放时冻结 timeline 重建。
我们：Store + 全量订阅（legacy 双跑）+ 500ms 轮询 refresh + **renderTimeline 全量 innerHTML 重建** + 播放时冻结（已有）。

**结构性差异**：
1. 新版"组件复用=不重建 DOM"（changelog 0.3.0 明写）；我们全量重建
2. 新版无"500ms 轮询全量刷新"；我们靠它做"人/AI 实时互看"（这是 AI 层需求，但实现代价是全量重建）
3. 新版拖动只改局部；我们拖段走全量 _emit
