# 编辑器内核差距对照 · 我们 vs OpenCut（2026-08-20 全面扫源码）

> 方法：OpenCut classic（685 TS 文件）分 4 模块由探索 agent 深度分析（数据模型/命令/交互/参数关键帧）+ 我读双方核心文件；我们项目（前端 3061 行 HTML + 9 个 JS 模块 + property/ 10 文件 + 后端 main.py 5033 行）逐层对照。
> 目的：**找出架构级差距，不打补丁**。用户判断"这不是小地方的问题，是架构问题"——本文档确认并列出差距。

---

## 零、核心结论（先看这个）

**OpenCut 的本质**：一切数据走**统一的 path 字符串**（`transform.positionX` 静态值在 `params`、动画在 `animations[path]`），一条路径打通 UI/插值/曲线/序列化；命令层用 **overlay diff + 单 command 提交**保证 undo；交互层用 **previewOverlay 临时层**不碰正式数据。

**我们的本质**：**5 套各自为政的数据**（volume/speed/transform/masks/animations 都是独立字段或独立面板），3 套互相不通的写入路径（面板值 / 关键帧 / 素材参数），全局广播 renderAll。

**差距 = 数据没统一 + 写入路径没打通 + 状态分层没做**。这就是"改一个出另一个"的根源。

---

## 一、数据模型层

| 维度 | OpenCut | 我们 | 差距影响 |
|---|---|---|---|
| 元素结构 | `Element{ params: ParamValues, animations?, effects[], masks[] }`——**params 统一放所有静态属性** | `seg{ volume, speed, transform{}, animations{}, masks[], ... }` 各字段平铺 | 没统一寻址，读/写/序列化各写各的 |
| transform | 静态值就是 `params["transform.positionX"]` | 独立 `seg.transform{x,y,scaleX,scaleY,rotation,opacity}`（Step0 刚加） | 与 volume/speed 不统一；贴纸还是旧结构 |
| 动画与静态共存 | `resolveAnimationPathValueAtTime(animations, time, params静态值)`——动画覆盖静态，无动画回落静态 | `resolveTransform`（三层解析）只覆盖 transform 6 属性 | 只通了 transform，volume/speed 关键帧没走同一读取路径 |
| 属性注册表 | `params/registry.ts`：字段定义含 keyframable/min/max/step——**同一份注册表驱动 UI/插值/曲线** | 无统一注册表：KF_PATHS / audio-panel / speed-panel / mask-panel 各写各的字段定义 | 字段定义三处重复，加属性要改 N 处 |

## 二、状态管理层

| 维度 | OpenCut | 我们 | 差距影响 |
|---|---|---|---|
| 文档态 vs UI 态 | **强制分层**：业务数据进 EditorCore managers（可序列化），UI 态进 zustand（仅偏好），互不污染 | Store.state.draft（文档）和 selectedKey/playheadUs（UI 态）**全在一个 Store** | 任何 UI 态变化触发 draft 全量渲染 |
| 通知机制 | 粗粒度广播 + **React selector 收敛**（重渲染节流下放） | 全局广播 `_emit → renderAll` 全量重渲；5.1 加了 subscribeSlice API **但没迁移** | 播放头/选中/拖拽都触发全量 renderAll |
| 选中态 | SelectionManager 三类互斥选择 + 快照支持 undo | Store.state.selectedKey/selectedKeys + selectedSegId | 无快照进 undo（撤销不恢复选中态） |

## 三、命令 / Undo 层

| 维度 | OpenCut | 我们 | 差距影响 |
|---|---|---|---|
| 命令模式 | Command 基类（execute/undo/redo 自带状态）+ CommandManager 双栈 + BatchCommand（逆序 undo）+ TracksSnapshotCommand | 后端 Api.cmd_mgr（Python 侧）+ save_state 自动快照（last_committed 对比）+ push_undo（已废弃空函数） | 已有快照式基础，但前端操作**未统一走命令入口**（直接 call API） |
| 拖动事务 | **previewOverlay diff + 松手一次 TracksSnapshotCommand** = 一次拖动一条 undo | preview-drag commit 是单次 update_segment_transform（一次 undo），但**无 overlay diff/事务概念** | 未来多属性拖动/缩放会多条 undo |
| 高频操作 | previewElements 写 overlay 不入栈，松手才 commit | PreviewInteraction（刚做）近似 overlay，但 commit 直接调后端 | 方向对，缺"一条命令包全部变化" |

## 四、交互层（预览拖动）

| 维度 | OpenCut | 我们 | 差距影响 |
|---|---|---|---|
| 状态机 | GestureSession: idle→pending→dragging→idle | previewDrag 局部变量 + PreviewInteraction（刚做） | 已有雏形 |
| 拖动中写哪 | **previewOverlay Map（不碰正式 tracks）**，渲染读 overlay 叠加 | 只改 el.style + PreviewInteraction.override | 近似但未进"渲染统一读"（renderPreview 不读 PreviewInteraction 除 applyKfTransform） |
| 提交 | commitPreview 生成 TracksSnapshotCommand 一条 undo | update_segment_transform 单命令 | 缺事务包装 |
| 命中 | 按 z-order + pointInRotatedRect + "已选中优先" | closest [data-preview-el]（取最上层 DOM） | 精度够 MVP，旋转命中不准 |
| 播放中 | 未硬禁（边界未防） | 禁止拖动（v2 约束） | 我们更保守，OK |

## 五、参数 / 关键帧层（用户感觉最痛）

| 维度 | OpenCut | 我们 | 差距影响 |
|---|---|---|---|
| 面板改值 ↔ 关键帧 | **useKeyframedParamProperty**：有动画 → 写关键帧（upsertPathKeyframe）；无动画 → 写静态值；onCommit=commitPreview 一次落库 | **没有等价物**：面板改值只写 seg（audio/speed 直接改字段），关键帧面板走 add_keyframe——**两套写入不互通** | **用户说的"参数得互通"就是这个** |
| draft 中间态 | usePropertyDraft：本地 draft + 失焦才 commit + 表达式求值 | Property Framework 有 DraftStore（两阶段） | 有基础，但没接"有动画写关键帧"逻辑 |
| 关键帧模型 | channel/keys + linear/hold/bezier + 贝塞尔 handle + 外推 | keys 线性插值（kfVal），**无 bezier/外推** | 曲线编辑器（用户想要的）做不了 |
| 关键帧标记 | 时间轴段上画菱形（timeline-element keyframe indicators） | **关键帧标记在曲线图（renderKfGraph），不在素材段上** | 用户截图指出"蓝色点不在素材上" |
| 数据流 | 面板读 = resolveAnimationPathValueAtTime(animations, time, params)；写 = 有动画写关键帧/无动画写静态 | 面板读 = seg 字段/kfVal 各写各；写 = 各面板直写 | 读写的"单一真相"缺失 |

## 六、差距优先级（重做顺序建议，非补丁）

```
D1  统一属性寻址：params 注册表（含 keyframable）——一表驱动 UI/插值/曲线
    ← 一切互通的地基（参考 OpenCut params/registry.ts）
D2  写入路径打通：useKeyframedParamProperty 等价物（面板改值→有动画写关键帧/无动画写静态值）
    ← 用户最痛"参数互通"
D3  状态分层：document(seg数据) ↔ interaction(拖动) ↔ ui(选中/播放头) 分离 + 细粒度订阅迁移（5.3 正是这个）
D4  拖动事务：overlay diff + 一次拖动一条 undo（参考 previewOverlay + TracksSnapshotCommand）
D5  关键帧增强：bezier 插值 + 素材段菱形标记 + 曲线编辑器（用户想要的）
D6  命令统一入口：前端所有写操作走统一 API 封装（Agent/MCP 复用）
```

**不是全部重写**——我们已有：Property Framework（Field/DraftStore）、PreviewInteraction + Refresh Lock、subscribeSlice API、后端命令栈。**D1-D4 是在现有地基上对齐架构**，D5 是增强，D6 是收口。
