## 0. 全局地图：两个世界、一条总线

OpenCut 的架构可以被一句话概括：**"一条命令总线（Intent → Command → State → History）贯穿所有可撤销的编辑动作，一个 EditorCore 单例管理全部领域状态，React 只做订阅渲染，Canvas 渲染由 rAF 循环驱动。"**

先给出全局模块地图，便于后续每一部分对号入座：

```
apps/web/src/
├── core/                    ← ★ 架构骨架：EditorCore 单例 + 12 个 Manager
│   ├── index.ts             ← EditorCore（组合根、依赖装配）
│   └── managers/            ← project/timeline/scenes/media/selection/playback/
│                               renderer/save/audio/commands/clipboard/diagnostics
├── commands/                ← ★ 命令系统（Intent→Command→History）
│   ├── base-command.ts      ← Command 抽象基类
│   ├── batch-command.ts     ← BatchCommand 组合命令
│   └── timeline/…           ← 全部具体命令（move/split/trim/keyframes/effects/masks…）
├── animation/               ← ★ 动画系统（binding + channel + keyframe）
├── timeline/                ← ★ 时间线领域模型 + 交互控制器 + 吸附/布局/放置
│   ├── types.ts             ← 时间线数据模型（Scene/Track/Element）
│   ├── controllers/         ← 交互控制器（drag/resize/keyframe/playhead/zoom/seek…）
│   ├── group-move/          ← 多选组移动求解
│   ├── group-resize/        ← 多选组裁剪求解
│   ├── placement/           ← 轨道放置（auto/explicit/overlap）
│   ├── snapping/            ← 吸附系统
│   └── update-pipeline.ts   ← element patch 派生/强制规则
├── preview/                 ← ★ 画布预览（视口、变换手柄、交互控制器、覆盖层）
├── selection/               ← 两套选中：EditorCore SelectionManager + 通用可选项 React Context
├── actions/                 ← ★ 动作注册表（快捷键→Intent 总线）
├── editor/                  ← React 绑定层（use-editor / cancel-interaction）
├── project/                 ← 项目类型定义
├── media/                   ← 媒体资产模型与处理
├── effects/ masks/ graphics/ text/ stickers/ subtitles/ sounds/  ← 内容域（注册式）
├── params/                  ← ParamDefinition 注册表
├── rendering/               ← Transform / BlendMode / 动画值解析
├── services/renderer/       ← ★ 渲染引擎（scene-builder → node tree → canvas/gpu）
├── services/storage/        ← ★ 持久化（IndexedDB + OPFS + 迁移）
├── wasm/                    ← MediaTime 整数 tick 模型
└── fps/ canvas/ guides/ retime/ ripple/ …        ← 横切工具
```

**核心分层关系（状态流总图）**：

```
React 组件 (只读订阅 + 触发交互)
   │  useEditor() useSyncExternalStore 订阅 9 个 Manager
   ▼
交互控制器 (Interaction Controller / Session)
   │  输入事件 → 本地 session → 预览更新（draft）或直接计算
   ▼
EditorCore Manager（领域状态入口）
   │  timeline.previewElements() / timeline.commitPreview()
   │  timeline.moveElements() / splitElements() / upsertKeyframes() …
   ▼
Command（命令对象，自包含：execute/undo/redo + savedState）
   │  editor.command.execute({ command })
   ▼
ScenesManager.updateSceneTracks() ← TimelineManager.updateTracks()
   │  写 Scene.tracks（不可变替换）→ notify
   ▼
订阅者（react 重渲染 / RenderTreeController 重建 node tree / SaveManager 防抖落盘 / AudioManager 同步）
```

## 第 1 部分：编辑器核心架构

### 1.1 EditorCore：一切的中心（组合根）

**是什么**：一个进程级单例，持有全部 12 个领域 Manager，是架构的"组合根"和唯一事实来源。

**文件**：`core/index.ts`

```ts
export class EditorCore {
  private static instance: EditorCore | null = null;
  public readonly timeline: TimelineManager;
  public readonly command: CommandManager;
  public readonly playback: PlaybackManager;
  public readonly scenes: ScenesManager;
  public readonly project: ProjectManager;
  public readonly media: MediaManager;
  public readonly renderer: RendererManager;
  public readonly save: SaveManager;
  public readonly audio: AudioManager;
  public readonly selection: SelectionManager;
  public readonly clipboard: ClipboardManager;
  public readonly diagnostics: DiagnosticsManager;
  // 构造函数里：registerDefaultEffects() / registerDefaultMasks() → 装配各 Manager
  // → playback.bindTimelineScope() → command.registerReactor(修剪空轨道) → save.start()
}
```

**关键设计**：
- **构造函数即装配**：启动时注册默认特效/蒙版定义、绑定播放器作用域、注册"命令后清空空轨道"的 reactor、启动自动保存。
- **命令是 Manager 之间的通信媒介**：Manager 不直接互相调用写操作，而是构造命令对象交给 `command.execute()`。
- React 通过 `useEditor()`（`editor/use-editor.ts`）拿到单例，并用 `useSyncExternalStore` 订阅其中 9 个 Manager（playback/timeline/scenes/project/media/renderer/selection/clipboard/diagnostics）。

### 1.2 project model（项目）

**是什么**：一个项目 = 元数据 + 场景列表 + 全局设置 + 版本号。

**数据结构**（`project/types.ts`）：

```ts
export interface TProject {
  metadata: TProjectMetadata;   // id, name, thumbnail?, duration, createdAt, updatedAt
  scenes: TScene[];             // 全部场景（含 main scene）
  currentSceneId: string;
  settings: TProjectSettings;   // fps, canvasSize, canvasSizeMode, background
  version: number;              // 存储迁移版本号 CURRENT_PROJECT_VERSION
  timelineViewState?: TTimelineViewState; // zoomLevel, scrollLeft, playheadTime
}
```

**由谁管理**：`ProjectManager`（`core/managers/project-manager.ts`）。内部持有 `active: TProject | null`、`savedProjects`、`migrationState`、`exportState`。

**职责**：
- `createNewProject()`：用 `buildDefaultScene()`（`timeline/scenes.ts`）构造主场景 → 组装 TProject → `storageService.saveProject()`。
- `loadProject()`：暂停自动保存 → 跑存储迁移 → 清空 media/scenes → 从存储加载 → `scenes.initializeScenes()` → 加载媒体 → 按需加载字体 → 生成缩略图。
- `saveCurrentProject()`：从 `scenes.getScenes()` 取最新场景快照，重算 duration，写回 `storageService`。
- `setActiveProject()` / `getActive()`：主动式项目指针。
- `export()`：委托 `renderer.exportProject()` 并暴露进度/取消。

**注意**：Project 的 `scenes` 字段只是**序列化入口**；运行时的场景状态活在 `ScenesManager` 里，`saveCurrentProject` 时才把两者同步。

### 1.3 scene model（场景）

**是什么**：一个"时间线世界"。包含 id、名称、是否主场景、轨道集合、书签、创建/更新时间。

**数据结构**（`timeline/types.ts`）：

```ts
export interface TScene {
  id: string;
  name: string;
  isMain: boolean;          // 主场景不可删除
  tracks: SceneTracks;
  bookmarks: Bookmark[];    // 书签（时间 + 可选 note/color/duration）
  createdAt: Date;
  updatedAt: Date;
}

export interface SceneTracks {
  overlay: OverlayTrack[];  // video/text/graphic/effect 轨道
  main: VideoTrack;         // 永远存在的一条主视频轨（锚定 0 点）
  audio: AudioTrack[];
}
```

**由谁管理**：`ScenesManager`（`core/managers/scenes-manager.ts`）。持有 `active: TScene | null` + `list: TScene[]`。

**关键职责**：
- `updateSceneTracks()`：**唯一修改轨道状态的入口**。不可变替换 active scene → 同步回 list → 同步回 `ProjectManager.activeProject.scenes` → notify。
- 场景级命令：CreateScene/DeleteScene/RenameScene/MoveBookmark/RemoveBookmark/ToggleBookmark/UpdateBookmark。
- `ensureMainScene()`（`timeline/scenes.ts`）：保证永远存在主场景；`getMainScene()` 作为 fallback。

**主轨锚定**：`update-pipeline.ts` 的 enforce 规则规定 main track 上第一个元素 startTime 被钳制到 0（视频项目以主轨起点为时间原点）。

### 1.4 timeline model（时间线/轨道）

**是什么**：场景内的"轨道集合"，分为三类：`overlay`（上叠加层，含 video/text/graphic/effect 轨道）、`main`（主视频轨）、`audio`（音频轨）。

**数据结构**（`timeline/types.ts`）：

```ts
export type TrackType = "video" | "text" | "audio" | "graphic" | "effect";

export interface VideoTrack extends BaseTrack { type: "video"; elements: (VideoElement|ImageElement)[]; muted: boolean; hidden: boolean; }
export interface TextTrack   extends BaseTrack { type: "text"; elements: TextElement[]; hidden: boolean; }
export interface AudioTrack  extends BaseTrack { type: "audio"; elements: AudioElement[]; muted: boolean; }
export interface GraphicTrackextends BaseTrack { type: "graphic"; elements: (StickerElement|GraphicElement)[]; hidden: boolean; }
export interface EffectTrack extends BaseTrack { type: "effect"; elements: EffectElement[]; hidden: boolean; }
```

**由谁管理**：`TimelineManager`（`core/managers/timeline-manager.ts`）。它不存轨道本身（轨道活在 `ScenesManager.active.tracks`），而是提供**全部轨道操作的语义 API** 并把它们翻译成命令：

| 操作 | Manager 方法 | 底层命令 |
|---|---|---|
| 增删轨道 | `addTrack/removeTrack` | `AddTrackCommand/RemoveTrackCommand` |
| 插入元素 | `insertElement` | `InsertElementCommand` |
| 移动（多选组） | `moveElements` | `MoveElementCommand` |
| 裁剪/更新 | `updateElements` / `updateElementTrim` | `UpdateElementsCommand`（走 update-pipeline） |
| 分割 | `splitElements` | `SplitElementsCommand` |
| 复制/删除 | `duplicateElements/deleteElements` | `DuplicateElementsCommand/DeleteElementsCommand` |
| 关键帧 | `upsertKeyframes/removeKeyframes/retimeKeyframe/updateKeyframeCurves` | `UpsertKeyframeCommand` 等 |
| 特效/蒙版 | `addClipEffect/updateClipEffectParams/…` | `AddClipEffectCommand` 等 |
| 预览草稿 | `previewElements/commitPreview/discardPreview` | `TracksSnapshotCommand` |
| 吸附 | — | `snapping/`（纯计算，无命令） |

**TimelineManager 还持有两个"临时状态"**：
- `previewOverlay: Map<elementId, Partial<TimelineElement>>` —— 拖动时的草稿叠加层
- `previewTracks: SceneTracks | null` —— 叠加后的预览轨道

`getPreviewTracks()` 优先返回 `previewTracks`，否则返回正式场景轨道。这是"渲染层永远读预览优先"的关键。

### 1.5 clip/element model（片段/元素）

**是什么**：轨道上的最小可编辑单元。判别联合（discriminated union），共 7 种：`audio / video / image / text / sticker / graphic / effect`。

**公共基座**（`timeline/types.ts`）：

```ts
interface BaseTimelineElement {
  id: string;
  name: string;
  duration: MediaTime;      // 时间线上可见时长
  startTime: MediaTime;     // 时间线起点
  trimStart: MediaTime;     // 源素材头部裁切
  trimEnd: MediaTime;       // 源素材尾部裁切
  sourceDuration?: MediaTime;
  animations?: ElementAnimations;  // ★ 动画绑定（见第 3 部分）
}
```

**类型专属字段**：

| 类型 | 独有字段 | 备注 |
|---|---|---|
| `VideoElement` | mediaId, transform, opacity, blendMode, volume, muted, retime, isSourceAudioEnabled, effects[], masks[], hidden | 引用媒体资产 |
| `ImageElement` | mediaId, transform, opacity, blendMode, effects[], masks[], hidden | 同上 |
| `TextElement` | content, fontSize, fontFamily, color, background, textAlign, fontWeight, fontStyle, textDecoration, letterSpacing, lineHeight, transform, opacity | 文字样式内联在元素上 |
| `StickerElement` | stickerId, intrinsicWidth/Height, transform, opacity | 贴纸是"id 引用 + 注册表解析" |
| `GraphicElement` | definitionId, params: ParamValues, transform, opacity, effects[], masks[] | 图形 = 定义 id + 参数表 |
| `EffectElement` | effectType, params | 效果层轨道上的元素 |
| `AudioElement` | sourceType(upload/library), mediaId/sourceUrl, volume, muted, buffer, retime | buffer 仅运行时存在，落盘时剥离 |

**类型级分组**（`timeline/types.ts` 底部）：
- `VISUAL_ELEMENT_TYPES`：video/image/text/sticker/graphic → 有 transform/opacity
- `MASKABLE_ELEMENT_TYPES`：video/image/graphic → 可挂蒙版
- `RETIMABLE_ELEMENT_TYPES`：video/audio → 可变速

**更新路径**：所有对 element 的 patch 都经过 `update-pipeline.ts` 的 `applyElementUpdate()`：先 apply patch，再跑 `deriveRules`（派生规则：retime → 重算 duration）和 `enforceRules`（强制规则：startTime ≥ 0、main track 锚定 0、duration 变化时钳制关键帧）。**更新永远不可变替换，元素对象不被原地修改。**

### 1.6 media model（媒体资产）

**是什么**：素材库中的原始文件描述。与时间线元素分离——元素通过 `mediaId` 引用资产。

**数据结构**（`services/storage/types.ts` 的 `MediaAssetData` + `media/types.ts` 的 `MediaAsset`）：

```ts
export interface MediaAsset extends Omit<MediaAssetData, "size"|"lastModified"> {
  id: string; name: string; type: "image"|"video"|"audio";
  size: number; lastModified: number;
  width?/height?/duration?/fps?/hasAudio?/ephemeral?;
  thumbnailUrl?: string;
  file: File;        // 运行时保留 File 引用
  url?: string;      // objectURL
}
```

**由谁管理**：`MediaManager`（`core/managers/media-manager.ts`）。持有 `assets: MediaAsset[]`。

**职责**：
- `addMediaAsset()`：追加到内存数组 → notify → `storageService.saveMediaAsset()`（元数据进 IndexedDB，文件进 OPFS）→ 失败回滚并提示配额。
- `removeMediaAssets()`：包 `RemoveMediaAssetCommand`（可撤销！）。
- `loadProjectMedia()` / `clearAllAssets()`：负责 objectURL 释放、videoCache/waveformCache 清空。
- 导入管线在 `media/processing.ts`（mediabunny 读视频 → 生成缩略图 → 上报 fps，触发 `project.ratchetFpsForImportedMedia`）。

**存储分库**（`services/storage/service.ts`）：项目 JSON 进 IndexedDB `video-editor-projects`；媒体元数据进 IndexedDB `video-editor-media-<projectId>`；媒体二进制进 OPFS `media-files-<projectId>`。

### 1.7 selection model（选中）

**是什么**：编辑器当前选中的内容，分三种互斥的选中种类：**元素 / 关键帧 / 蒙版点**。

**数据结构**（`selection/editor-selection.ts`）：

```ts
export interface EditorSelectionSnapshot {
  selectedElements: ElementRef[];                 // {trackId, elementId}
  selectedKeyframes: SelectedKeyframeRef[];       // {trackId, elementId, propertyPath, keyframeId}
  keyframeSelectionAnchor: SelectedKeyframeRef | null;  // shift 范围选锚点
  selectedMaskPoints: SelectedMaskPointSelection | null; // {trackId, elementId, maskId, pointIds[]}
}
```

**由谁管理**：`SelectionManager`（`core/managers/selection-manager.ts`）。持有上述四个字段 + 订阅者集合。

**关键操作**：
- 三种 set 方法互相清除对方（同一时刻只有一种选中种类活跃）：`setSelectedElements` / `setSelectedKeyframes` / `setSelectedMaskPoints`。
- `getActiveSelectionKind()`：返回 `"mask-points" | "keyframes" | "elements" | null`（优先级：蒙版点 > 关键帧 > 元素）。UI（如 delete 键）按此分发。
- **与命令系统集成**：`getSnapshot()` 供 CommandManager 在执行前保存；`applySelectionPatch()` 应用命令返回的 `CommandResult.selection`；`restoreSnapshot()` 在 undo 时恢复。`clearMostSpecificSelection()` 用于 ESC 逐级取消。

**第二套选中**：`selection/selectable-surface.tsx` + `selection/state.ts` 是**通用可选项 React Context**（用于素材面板等列表 UI），与时间线选中完全解耦。时间线选中只走 `SelectionManager`。

### 1.8 command model（命令）

**是什么**：一切可撤销编辑动作的载体。每个命令是一个**自包含的对象**：构造时带参数，`execute()` 读当前状态、保存 `savedState`、写新状态、返回可选的 `CommandResult.selection`；`undo()` 用 savedState 还原。

**基类**（`commands/base-command.ts`）：

```ts
export abstract class Command {
  abstract execute(): CommandResult | undefined;   // CommandResult 携带 selection patch
  undo(): void { throw new Error("Undo not implemented"); }
  redo(): CommandResult | undefined { return this.execute(); }  // 默认重放 execute
}
```

**组合**（`commands/batch-command.ts`）：`BatchCommand` 依序执行子命令，undo 时**逆序**逐个 undo，redo 时正序重放。

**注册/组织**：没有集中注册表——每个命令类是独立文件，Manager 直接 import。`commands/timeline/index.ts` 作为桶导出。

**与 Manager 的关系（反向依赖）**：命令通过 `EditorCore.getInstance()` 服务定位拿到 Manager 并调用其写方法（如 `editor.timeline.updateTracks(updatedTracks)`）。**命令不 return 新状态给调用方，而是自己负责把状态写回 Manager。**

### 1.9 undo/redo model（撤销）

**是什么**：基于命令对象的双栈历史。

**由谁管理**：`CommandManager`（`core/managers/commands.ts`）。内部：

```ts
interface CommandHistoryEntry {
  command: Command;
  previousSelection: EditorSelectionSnapshot;   // 执行前选中快照
  selectionOverride?: EditorSelectionSnapshot;  // 有 selection 意图时才恢复
}
private history: CommandHistoryEntry[] = [];    // undo 栈
private redoStack: CommandHistoryEntry[] = [];  // redo 栈
```

**execute() 流程**：
1. （可选，开启 ripple 时）快照 `beforeTracks`
2. 快照 `previousSelection`
3. `command.execute()`
4. （开启 ripple 时）`computeRippleAdjustments` + `applyRippleAdjustments`，用 `timeline.updateTracks` 应用波纹调整
5. `applySelectionOverride(result)`：若命令返回 selection patch，应用到 SelectionManager 并记录 override
6. `runReactors()`：跑注册的 reactor（默认 reactor 会修剪空轨道）
7. 推入 history，清空 redoStack

**push()（不执行直接入栈）**：预览提交路径用——`commitPreview()` 已经更新了轨道，只需把 `TracksSnapshotCommand`（记录 before/after）push 进历史。

**undo()**：弹出 history → `command.undo()` → **仅当命令有 selectionOverride 时**恢复 previousSelection（无选择意图的命令不动选中，保留用户点击带来的 UI 选中变化）→ 推入 redoStack。
**redo()**：对称执行 `command.redo()`。

**两个全局开关**：
- `isRippleEnabled`：开启时每次 execute 前后对比 tracks，自动计算波纹位移（`ripple/` 模块）并二次更新。
- `clear()`：切项目时清空。

### 1.10 playback model（播放）

**是什么**：播放头时间、播放状态、音量，以及"播放时随时间推进播放头"的时钟。

**由谁管理**：`PlaybackManager`（`core/managers/playback-manager.ts`）。持有 `currentTime: MediaTime`、`isPlaying`、`volume/muted`、`isScrubbing`。

**时钟机制**：
- `play()`：从当前时间用 `requestAnimationFrame` 启动 `updateTime` 循环。
- `updateTime()`：`performance.now()` 差值与播放起点相加 → `roundFrameTime()` 按 fps 取整 → 越界自动 `pause()` 并 seek 到末尾。
- `seek()`：直接设置 currentTime → notify → notifySeek。
- `bindTimelineScope()`：订阅 timeline/scenes，时间线时长变化时自动钳制 currentTime，播放到头自动停。
- 订阅通道有三条：`subscribe`（状态变化）、`onUpdate`（播放逐帧）、`onSeek`（seek 事件）。AudioManager 靠这些同步音频调度。

**重要**：PlaybackManager **不直接驱动渲染**。渲染靠 `preview/components/index.tsx` 的 `useRafLoop`，每帧读 `playback.getCurrentTime()` 并比较帧号缓存，只有帧号变化才真正渲染。

### 1.11 rendering model（渲染）

**是什么**：把"场景（tracks + media + settings）"翻译成"某一时刻的一帧图像"的过程。分为**构建**（scene-builder）与**解析**（resolve）两阶段，Canvas 2D 与 GPU 两条后端。

**流程**（`services/renderer/` + `preview/components/index.tsx`）：

```
tracks + mediaAssets + canvasSize + background
  → buildScene()                     (services/renderer/scene-builder.ts)
  → RootNode（节点树：VideoNode/ImageNode/TextNode/StickerNode/GraphicNode/
             EffectLayerNode/BlurBackgroundNode/ColorNode）
  → editor.renderer.setRenderTree({ renderTree })   (RendererManager)
  → rAF 循环 (preview/components/index.tsx)
  → renderer.render({ node, time })
      → resolveRenderTree()  (services/renderer/resolve.ts：每个节点按 time 解析
                              transform/opacity/effects/masks/文字布局)
      → CanvasRenderer (services/renderer/canvas-renderer.ts) 或 GPU (gpu-renderer.ts)
      → 输出 canvas（挂进 DOM）
```

**两条后端**：
- `CanvasRenderer`：2D Canvas，`renderToCanvas()`。
- GPU：`gpu-renderer.ts` + `compositor/wasm-compositor.ts`（wgpu 渲染）。`EditorProvider` 里 `initializeGpuRenderer()` + `renderer.setDegraded(!isGpuAvailable())` 做降级切换。

**帧去重**：`preview/components/index.tsx` 缓存 `lastFrameRef`（当前帧号）与 `lastSceneRef`（render tree 引用），两者都没变就跳过渲染——这是性能关键。

**导出**：`RendererManager.exportProject()` → `SceneExporter`（`services/renderer/scene-exporter.ts`）逐帧导出；`createSnapshot()` 用 `CanvasRenderer.renderToCanvas` 截图。

## 第 2 部分：用户操作链

> 通用说明：OpenCut 的交互遵循一种**"会话（session）模式"**——每个拖拽/点击是一个 `interaction session`，控制器内部维护 `{kind:"idle"|"pending"|"dragging"|…}` 状态机。分两类写路径：
> - **草稿路径（draft）**：拖动过程中改 `previewOverlay`（不落正式状态），松手时 `commitPreview()` 用 `TracksSnapshotCommand` 入栈。用于：画布变换、时间线裁剪、属性面板拖动。
> - **计算路径（compute）**：拖动过程只做几何/放置计算 + 视觉指示（drag-line/drop-target），松手时一次性构造命令提交。用于：时间线移动元素。
>
> 另外 ESC 取消有统一机制：`editor/cancel-interaction.ts` 的 `registerCanceller/cancelInteraction`，任何进行中的 session 注册取消函数，"cancel-interaction" 动作触发全部取消。

### 2.1 拖动素材（时间轴上移动）

```
用户按住素材拖动（鼠标左键）
  ↓ 触发层  timeline-element.tsx → onMouseDown → ElementInteractionController.onElementMouseDown
            (timeline/controllers/element-interaction-controller.ts)
  ↓ 交互层  session: pending → (越过拖拽阈值 TIMELINE_DRAG_THRESHOLD_PX) → dragging
            handleMouseMove → frameSnappedMouseTime(按fps取整) → snapResult(吸附)
            → buildMoveGroup(多选组) + resolveGroupMoveForDrop(计算目标轨道/新轨道)
            → 视觉：ElementDragView + drop-target + snap-indicator（纯 UI，不改状态）
  ↓ 状态层  拖动期间【不改任何领域状态】——只更新本地 session 的 currentTime/dropTarget
  ↓ 命令层  handleMouseUp → 判断 didMove → timeline.moveElements({moves, createTracks})
            → MoveElementCommand.execute()
              (commands/timeline/element/move-elements.ts)
            → 内部：建新轨道 → 逐元素移动到目标轨 + 改 startTime
  ↓ 历史层  CommandManager.execute → history.push + reactor(修剪空轨道) + ripple(可选)
  ↓ 渲染层  timeline.updateTracks → notify → RenderTreeController 重建 node tree
            → rAF 帧号变化 → 画布重绘；时间线 DOM 重渲染
  ↓ 落盘    SaveManager 订阅 scenes/timeline → 800ms 防抖 → storageService.saveProject
```

**要点**：时间线移动**不用 previewOverlay**，而是"拖动时只画指示、松手一次性提交"，因为移动是离散的轨道归属变化，不需要帧级预览。组移动由 `group-move/`（build-group → resolve-move → snap）纯函数求解。

### 2.2 裁剪素材（trim / resize）

```
用户拖素材左右边缘
  ↓ 触发层  timeline-element.tsx → onResizeStart → ResizeController.onResizeStart
```

**要点**：裁剪是典型的"草稿路径"——拖动中每帧都更新 `previewOverlay`，画面即时反馈；松手先 `discardPreview` 再提交正式命令（防止 overlay 与命令叠加出双重修改）。

### 2.3 分割素材（split）

```
用户按 S（或编辑菜单）触发 split action
  ↓ 触发层  actions/use-editor-actions.ts → useActionHandler("split")
            → 取选中元素 或 getElementsAtTime(播放头处元素)
  ↓ 命令层  timeline.splitElements({elements, splitTime})
            → SplitElementsCommand
              (commands/timeline/element/split-elements.ts)
            → 每个元素：计算相对时间 → 左右可见时长 →

```

分两种语义：**① 画布视口缩放（view 级）② 元素变换缩放（数据级）**。

**要点**：画布元素变换是"草稿路径 + push 入栈"的教科书实现——`commitPreview` 不是执行命令改状态，而是**把已经发生的状态变化（before/after）打包成命令直接入栈**。

## 第 3 部分：数据模型（重点：OpenCut 如何表达动画）

### 3.1 动画数据组织方式：Binding + Channel 双层模型

动画不在元素上直接存"keyframes[]"，而是存在 `element.animations` 里，分两层：

```ts
// animation/types.ts
export interface ElementAnimations {
  bindings: ElementAnimationBindingMap;  // Record<propertyPath, BindingInstance>
  channels: ElementAnimationChannelMap;  // Record<channelId, AnimationChannel>
}
```

**Channel（通道）—— 真正存关键帧的地方**：
```ts
export interface ScalarAnimationChannel {
  kind: "scalar";
  keys: ScalarAnimationKey[];   // { id, time(相对元素起点), value, segmentToNext:
                                //   "step"|"linear"|"bezier", tangentMode,
                                //   leftHandle/rightHandle: CurveHandle{dt,dv} }
  extrapolation?: { before: "hold"|"linear"; after: "hold"|"linear" };
}
export interface DiscreteAnimationChannel {
  kind: "discrete";
  keys: DiscreteAnimationKey[];  // { id, time, value: boolean|string }
}
```
每个 scalar channel 代表**一个数值维度**（如 X 位移、R 通道）；每个 keyframe 携带插值类型、贝塞尔手柄、切线模式——**缓动曲线是数据的一部分**，落在 keyframe 上（`segmentToNext` + `leftHandle/rightHandle`），由 `animation/interpolation.ts` + `animation/bezier.ts` 求值。

**Binding（绑定）—— 把"属性路径"映射到"通道组合"**：
```ts
export interface NumberAnimationBinding {
  path: AnimationPath;         // 如 "transform.positionX"
  kind: "number";
  components: [{ key: "value"; channelId: string }];
}
export interface Vector2AnimationBinding {
  path: AnimationPath; kind: "vector2";
  components: [{key:"x";channelId},{key:"y";channelId}];   // 2 个通道
}
export interface ColorAnimationBinding {
  path: AnimationPath; kind: "color"; colorSpace: "srgb-linear";
  components: [{key:"r"…},{key:"g"…},{key:"b"…},{key:"a"…}];  // 4 个通道，线性空间
}
export interface DiscreteAnimationBinding {
  path: AnimationPath; kind: "discrete";
  components: [{key:"value";channelId}];
}
```

**关系总结**：`ElementAnimations = { bindings: 属性→绑定, channels: channelId→关键帧序列 }`。绑定是"语义/读法"，通道是"数据/存法"。一个 color 属性 = 4 个 scalar 通道各存一组关键帧；一个 vector2 = 2 个通道。channelId 规范为 `${path}:${componentKey}`（`buildBindingChannelId`，`animation/binding-values.ts`）。

**解析读取**（`animation/resolve.ts`）：`resolveAnimationPathValueAtTime` → 查 binding → 对每个 component 查 channel → `getChannelValueAtTime`（interpolation.ts，支持 extrapolation 外推）→ `composeAnimationValue`（binding-values.ts）合成回属性值。渲染层 `rendering/animation-values.ts` 用它对 transform/opacity 逐字段解析。

### 3.2 参数（params）注册与读写

**ParamDefinition 统一模型**（`params/index.ts`）：四种类型——`number / boolean / color / select`，每个定义含 `key / label / type / default / min / max / step / displayMultiplier / unit / shortLabel` 等。`ParamValues = Record<string, number|string|boolean>`。

**注册表**：`params/registry.ts` 的 `DefinitionRegistry<K, V>` 泛型类（register/has/get/getAll），被三类内容域复用：
- 图形：`graphics/registry.ts` 的 `GraphicsRegistry`（`registerDefaultGraphics` 在启动/按需时注册）
- 特效：`effects/registry.ts` 的 `effectsRegistry` + `registerDefaultEffects`（`core/index.ts` 启动注册）
- 蒙版：`masks/registry.ts`（同样启动注册）

**默认值构建**：`buildDefaultParamValues(params)` 遍历定义取 default。特效实例 `buildDefaultEffectInstance`（`effects/index.ts`）。

**读写路径**：
- 静态写：`GraphicElement.params[key]` / `EffectElement.params[key]` 直接改元素字段（经 `UpdateElementsCommand`）。
- 动画化写：`graphic-param-channel.ts` / `effect-param-channel.ts` 把参数转成动画路径——`params.<key>`（graphic）与 `effects.<effectId>.params.<key>`（effect）——再走 binding/channel。
- 关键 `resolveAnimationTarget`（`timeline/animation-targets.ts`）：把"属性路径"统一解析成 `AnimationPathDescriptor`（kind / defaultInterpolation / coerceValue / getBaseValue / setBaseValue）。graphic/effect 参数路径从这里拿到与内建属性完全一致的动画读写能力。**coerceValue 是运行时守卫**，用于拒绝持久化/粘贴/程序化输入里的非法值。

### 3.3 特效（effects）与蒙版（masks）的挂载

**特效**（`effects/types.ts`）：
```ts
export interface Effect {
  id: string;
  type: string;            // 查 effectsRegistry
  params: ParamValues;
  enabled: boolean;
}
```
- 挂载：`VideoElement.effects?: Effect[]` / `ImageElement.effects` / `TextElement.effects` / `StickerElement.effects` / `GraphicElement.effects`。
- 渲染：`EffectDefinition.renderer`（`passes: EffectPassTemplate[]` 或 `buildPasses`）→ `resolveEffectPasses`（effects/index.ts）→ shader + uniforms。模糊特效示例 `effects/definitions/blur.ts`。
- 独立轨道：`EffectElement`（type "effect"）可以整层存在于 effect 轨道，渲染成 `EffectLayerNode`（整层滤镜）。
- 特效参数动画化：`effects.<effectId>.params.<key>`（`effect-param-channel.ts`），命令 `UpsertEffectParamKeyframeCommand`。
- 特效顺序：`reorderClipEffects` 命令。

**蒙版**（`masks/types.ts`）：9 种蒙版类型（split/cinematic-bars/rectangle/ellipse/heart/diamond/star/text/custom）。
```ts
export interface Mask { id: string; type: MaskType; params: <各类型参数> }
```
- 挂载：`MASKABLE_ELEMENT_TYPES`（video/image/graphic）的 `masks?: Mask[]`。
- 每个 MaskDefinition 含 `renderer`（buildPath/buildStrokePath/renderMask）、`interaction`（手柄/覆盖层/吸附）、`features`、`isActive`、`buildDefault`、`computeParamUpdate`。
- 蒙版参数含公共基座 `BaseMaskParams`：feather/inverted/strokeColor/strokeWidth/strokeAlign。
- 命令集（`commands/timeline/element/masks/`）：RemoveMask/ToggleMaskInverted/InsertCustomMaskPoint/DeleteCustomMaskPoints。
- 蒙版点选中进入 SelectionManager（`selectedMaskPoints`），可被 delete 键删除（`delete-selected` action 的 "mask-points" 分支）。

### 3.4 时间表示：MediaTime 整数 tick

**文件**：`wasm/media-time.ts` + Rust `opencut-wasm`。

```ts
export type MediaTime = number & { readonly __mediaTime: unique symbol }; // 品牌类型
export const TICKS_PER_SECOND = …;   // 每秒 tick 数（wasm 边界）
export function mediaTime({ticks})      // 只能从整数 tick 构造（dev 断言）
export function roundMediaTime({time}) // 小数 → 就近 tick（half away from zero）
export function mediaTimeFromSeconds / mediaTimeToSeconds
export function roundFrameTime({time, fps})  // 按帧率取整
export function lastFrameMediaTime / snapSeekMediaTime
```

- **时间是整数 tick 计数**，品牌类型在类型层阻止直接写裸 number。
- 帧率模型：`FrameRate = { numerator, denominator }`（如 30fps = `{30,1}`），默认 `DEFAULT_FPS = {numerator:30, denominator:1}`（`fps/defaults.ts`）。帧号计算：`round(TICKS_PER_SECOND * denominator / numerator)`。
- 所有时间运算走 `addMediaTime/subMediaTime/maxMediaTime/minMediaTime/clampMediaTime`（保证不丢品牌 + 保持整数）。
- 播放 seek 时 `snapSeekMediaTime` 吸附到帧；拖动按 fps `roundFrameTime` 取整。

### 3.5 该模型对长期扩展的影响分析

> 分析方法：基于已实现的机制，评估"要加这个能力，是在已有机制上加码还是新造系统"。

| 能力 | 在该模型下 | 依据（源码机制） |
|---|---|---|
| **缓动曲线 easing** | ✅ **容易（已实现）**。贝塞尔缓动是原生能力 | keyframe 的 `segmentToNext: "bezier"` + `leftHandle/rightHandle: CurveHandle{dt,dv}` + `bezier.ts` 求解；graph-editor 组件（`timeline/components/graph-editor/`）已提供完整曲线编辑器 UI |
| **表达式 expression** | ⚠️ **中等**。模型里没有表达式节点，但 **binding 层天然适合**：expression 本质是"组件值来源从 keyframe 通道换成表达式解析器"。需要一个 `ExpressionBinding`（新 kind）+ 通道求值分支。阻碍：`AnimationBindingKind` 是封闭联合（types.ts 里 `"number"|"vector2"|"color"|"discrete"`），需放宽为开放联合或加 kind | `binding-values.ts` 的 `composeAnimationValue/decomposeAnimationValue` 已把读值抽象为"组件→通道"，表达式可注入为通道来源 |
| **AI 命令 AI command** | ✅ **容易**。所有编辑操作都有明确命令入口，AI 只需构造 Command 或调 Manager 方法 | 见第 5 部分；命令是自包含对象，无 UI 依赖；`upsertKeyframes` 接受任意 `keyframes[]` 数组可直接程序化批量打点 |
| **复制粘贴 copy/paste** | ✅ **容易（已实现）**。且是命令级的 | `clipboard/` 双层 handler（elements/keyframes）→ `PasteCommand`/`PasteKeyframesCommand`；元素序列化 `CreateTimelineElement` 不含 id（粘贴时新生成） |
| **嵌套时间线 nested timeline** | ❌ **困难（模型不支持）**。当前元素是叶子节点（直接引用 mediaId 或 definitionId），没有"子时间线"概念。需要：新增一种 `TimelineClipElement`（持子 SceneTracks 或子 project 引用）+ 渲染节点支持递归 + 深度解析 | `timeline/types.ts` 的 `BaseTimelineElement` 无嵌套字段；`scene-builder.ts` 是扁平的 track→node 映射；`getElementLocalTime/resolveAnimationPathValueAtTime` 只支持单层 localTime |
| **多场景（已有，可作为嵌套的起点）** | scenes 是平级列表，不能互相引用，但已是"时间线容器"的最小单元 | `project/types.ts` 的 `scenes: TScene[]` + `currentSceneId` |

**总体判断**：动画模型是**"属性路径 → 绑定 → 通道 → 关键帧"的四层解耦**，路径层负责"写回元素"（property-registry + animation-targets），通道层负责"插值求值"。这个分层对**缓动、表达式、AI 打点、复制粘贴都非常友好**（因为它们都在通道或路径层注入），但对**嵌套时间线**不友好（需要破坏叶子模型或引入新的容器元素）。若长期需要嵌套，建议在 `BaseTimelineElement` 增加可选 `children` 容器类型，并让 `resolveAnimationTarget` 与 `scene-builder` 递归化——这是已知的模型边界，不是 bug。

## 第 4 部分：渲染架构（什么时机做什么）

### 4.1 四类状态的时机总表

| 时机 | 改什么 | 谁触发 | 例子 |
|---|---|---|---|
| **交互中（拖动/滚动/悬停）** | **临时状态**：interaction session（本地）、`timeline.previewOverlay`、视口 zoom/pan（React state）、snap-indicator | 交互控制器（`timeline/controllers/*`、`preview/controllers/*`） | 拖元素→updateDropTarget；拖裁剪→previewElements；Ctrl+滚轮→scaleZoom |
| **交互结束（mouseup/commit）** | **正式状态**：`ScenesManager.active.tracks`（经 `timeline.updateTracks`） | 命令 execute / `commitPreview` | MoveElementCommand；TracksSnapshotCommand |
| **每次正式状态变化后** | **订阅者**（DOM 重渲染） | Manager notify → `useEditor` useSyncExternalStore | 时间线组件、属性面板、场景视图重渲染 |
| **正式状态变化且轨道/媒体/背景变化后** | **渲染树**（render tree 重建） | `RenderTreeController`（preview/components/index.tsx）useDeepCompareEffect → `buildScene` → `renderer.setRenderTree` | 加/删/移元素、改参数、改背景 |
| **播放/seek 每次帧变化后** | **画布像素** | rAF 循环（`useRafLoop`）→ `renderer.render({node, time})`（帧号缓存去重） | 播放头推进、拖播放头、打点跳到新帧 |
| **防抖 800ms 后** | **磁盘**（IndexedDB/OPFS） | SaveManager（订阅 scenes+timeline） | 任何编辑后自动保存 |
| **导出时** | **视频文件** | `project.export()` → SceneExporter | 逐帧导出 |

### 4.2 状态 vs 草稿的边界（本架构最重要的约定）

**正式状态（committed）**：`ScenesManager.active.tracks`（TScene.tracks），是命令执行后的结果，是保存/导出/渲染树的依据。

**草稿状态（draft）**：`TimelineManager.previewOverlay + previewTracks`，是"预览优先"的唯一来源：
- `getPreviewTracks()` = `previewTracks ?? activeScene.tracks`——**渲染层永远优先读草稿**（`preview/components/index.tsx` 的 `RenderTreeController`、`useElementPreview` hook 都读它）。
- 写入口只有 `timeline.previewElements({updates})`；提交 `commitPreview()`；丢弃 `discardPreview()`。
- **用途**：画布变换手柄、时间线裁剪、属性面板拖动滑块（`useKeyframedParamProperty.onPreview`）。

**为什么草稿不直接改正式状态**：因为每次 mouseup 才应该产生一个"可撤销的历史条目"。拖动中改正式状态会导致一帧一历史；草稿层把 N 帧变化折叠成一个 `TracksSnapshotCommand(before→after)`。

**注意两套并存的"不落正式状态的机制"**：
1. **previewOverlay 草稿**：写元素字段（transform/trim 等），提交时折叠成 TracksSnapshotCommand。
2. **session 本地状态**（ElementInteractionController/KeyframeDragController）：拖动中只在 session 里算、只画视觉指示，**根本不碰 previewOverlay**，松手一次性构造语义命令（MoveElementCommand / RetimeKeyframeCommand）。
   - 规律：**逐帧数值变化且需要画面反馈**（transform/trim/参数）→ 用草稿层；**离散的归属/时间跳变**（移动轨道、关键帧时间）→ 用 session + 提交命令。

### 4.3 DOM 更新时机

- **React 渲染**：靠 `useEditor(selector)` 订阅，manager 每次 `notify()` 触发 `useSyncExternalStore` 检查（浅比较 selector 返回值），变了才重渲染。selector 模式（`editor/use-editor.ts`）让组件只订阅自己关心的切片（如 `e.timeline.getPreviewTracks()`）。
- **Canvas 渲染**：`preview/components/index.tsx` 挂输出 canvas（GPU 渲染时直接挂 wgpu 输出画布），`useRafLoop` 每帧：
  ```ts
  frame = floor(renderTime / ticksPerFrame);
  if (frame === lastFrameRef.current && renderTree === lastSceneRef.current) return; // 帧去重
  renderer.render({node, time});  // 异步，renderingRef 防重入
  ```
  → **画布只在新帧号或新 render tree 时重绘**，且 render tree 引用不变时纯 seek 靠帧号去重跳过。

### 4.4 commit 时机汇总

| 场景 | commit 方式 | 历史行为 |
|---|---|---|
| 画布变换手柄 mouseup | `timeline.commitPreview()` → TracksSnapshotCommand | `command.push`（状态已更新，仅入栈） |
| 时间线裁剪 mouseup | `discardPreview()` + `updateElements` → UpdateElementsCommand | `command.execute`（重新计算+入栈） |
| 时间线移动 mouseup | `moveElements` → MoveElementCommand | `command.execute` |
| 关键帧拖动 mouseup | `commitDrag` → RetimeKeyframeCommand(s) | `command.execute`（多个走 BatchCommand） |
| 属性面板拖动 mouseup | `usePropertyDraft.commit` → `commitPreview` 或 `updateElements` | push 或 execute |
| 分割/删除/粘贴/特效/蒙版 | 直接命令 | `command.execute` |
| ESC 取消 | `discardPreview()` / `controller.cancel()` | 不入历史 |

### 4.5 渲染与播放的耦合

- PlaybackManager 只维护 `currentTime`，不主动触发渲染；渲染由 rAF 轮询帧号。
- AudioManager 订阅 playback（`onSeek`/`subscribe`）与 timeline/media，用 lookahead 调度（`scheduleTimer` 500ms + 2s 预取）提前解码缓冲（`audio-manager.ts`）。
- 渲染树在播放中保持不变（除非轨道变化），因为帧号去重保证了"seek/播放到未变化帧不重绘"。

## 第 5 部分：AI Agent 可操作性

### 5.1 总体判断

OpenCut 的编辑动作**几乎全部走 "Intent → Command → State Change → History" 链**，命令层是干净的程序化接口。但需要区分三类：

| 类别 | 可程序化调用 | 说明 |
|---|---|---|
| **A. 有命名 action（intent 总线）** | ✅ `invokeAction("split")` / 直接调 Manager 方法 | 快捷键/菜单/程序共用同一 handler（`use-editor-actions.ts`） |
| **B. 有 Manager 语义 API（无 action 名）** | ✅ `editor.timeline.*` / `editor.media.*` / `editor.scenes.*` 等 | 全部内部走 Command，天然可撤销 |
| **C. 硬编码在 UI / 纯展示态** | ❌ 无法/无需程序化 | 画布视口缩放、吸附线指示、pan/zoom、菜单布局、onboarding |

**结论**：OpenCut 没有独立的"AI API 层"，但 **Manager 层本身就是程序化 API**。一个 AI Agent 只要持有 `EditorCore` 单例（或构造命令对象），就能执行任何可撤销编辑。硬编码于 UI 的部分仅剩视口/展示类交互。

### 5.2 每个动作的自动化评估清单

**✅ 可直接程序化（有明确命令/Manager 入口）**：

| 动作 | 调用路径（代码实证） |
|---|---|
| 插入元素 | `timeline.insertElement({element, placement})` → `InsertElementCommand`（`commands/timeline/element/insert-element.ts`，placement 支持 explicit/auto） |
| 移动元素 | `timeline.moveElements({moves, createTracks})` → `MoveElementCommand` |
| 裁剪 | `timeline.updateElements` / `updateElementTrim` → `UpdateElementsCommand`（走 update-pipeline） |
| 分割 | `timeline.splitElements` → `SplitElementsCommand`（含 retainSide） |
| 删除 | `timeline.deleteElements` → `DeleteElementsCommand` |
| 复制粘贴 | `clipboard.copy()/paste()`（内存剪贴板）或直接构造 `PasteCommand` |
| 关键帧 | `timeline.upsertKeyframes/removeKeyframes/retimeKeyframe/updateKeyframeCurves/upsertEffectParamKeyframe` → 对应命令（**批量数组输入，天然适合 AI 打点**） |
| 特效 | `addClipEffect/removeClipEffect/toggleClipEffect/reorderClipEffects/updateClipEffectParams` |
| 蒙版 | 添加无专门命令——UI 用 `buildDefaultMaskInstance`（`masks/index.ts`）构造实例后走 `updateElements` 补丁 `element.masks`；删除/反选/加点有命令：`removeMask/toggleMaskInverted/insertCustomMaskPoint/deleteCustomMaskPoints` |
| 轨道 | `addTrack/removeTrack/toggleTrackMute/toggleTrackVisibility` |
| 场景 | `scenes.createScene/deleteScene/renameScene/switchToScene/toggleBookmark/…` |
| 媒体 | `media.addMediaAsset/removeMediaAssets`（remove 可撤销） |
| 播放 | `playback.play/pause/seek/setVolume/mute` |
| 撤销重做 | `command.undo()/redo()`；ripple 开关 `command.isRippleEnabled` |
| 项目设置 | `UpdateProjectSettingsCommand`（`commands/project/update-project-settings.ts`） |
| 其他编辑 | `toggleElementsMuted/toggleElementsVisibility/toggleSourceAudioSeparation` |

**⚠️ 半可程序化（走 UI 组件或需要对象引用）**：
| 动作 | 现状 |
|---|---|
| 拖入外部文件 | 文件→媒体导入在 `DragDropController.executeFileDrop` → `processMediaAssets`（`media/processing.ts`），有 async 处理管线可复用，但入口绑在 React DragEvent 上 |
| 画布元素拖动（transform handle） | 底层是 `TransformHandleController`（class，可独立实例化），但依赖 viewport adapter / React 事件；**数据层等价物**：`updateElements({transform})` 或 `upsertKeyframes` 已可程序化 |
| 文字编辑 | 双击进入 `text-edit-overlay.tsx` 的 contentEditable，但改内容本身走 `updateElements({content})` |
| 渲染树/导出 | `renderer.setRenderTree/buildScene/render`、`project.export()` 均可调用，但通常由 UI 驱动 |

**❌ 硬编码于 UI / 无程序化入口**：
| 动作 | 说明 |
|---|---|
| 画布缩放/平移 | `preview-viewport.tsx` 的 React context，纯展示态，不进状态 |
| 吸附线/预览叠加层 | `preview/overlays.ts` + snap-indicator，纯 UI |
| 时间线缩放/滚动 | `ZoomController/zoom-utils.ts` + `useScrollPosition`，属于 `timeline-view-state`（TimelineViewState 仅在部分场景持久化） |
| 快捷键配置 | `actions/keybindings-store.ts` + migrations，用户偏好 |
| 面板布局 | `editor/panel-store.ts`、resizable 组件，UI 态 |
| 预览 guide/grid | `preview-store.ts`（zustand persist），偏好态 |

### 5.3 AI 接入该架构的建议路径（基于现有机制，非新设计）

1. **首选 Manager API**：`EditorCore.getInstance()` → 各 Manager 方法。所有调用自动获得：撤销历史、选中管理、渲染刷新、自动保存。
2. **复合操作用 BatchCommand**：`new BatchCommand([cmd1, cmd2])` 原子入历史，undo 一次回退整批。
3. **批量关键帧**：`timeline.upsertKeyframes({keyframes: [...]})` 接受数组，天然支持 AI 一次打多点；值经 `coerceValue` 校验。
4. **动作总线**：有键盘/菜单语义的动作走 `invokeAction(action, args)`，可与用户共享快捷键语境。
5. **注意选中副作用**：命令可返回 `CommandResult.selection` 改变选中（如分割后选中右侧）；AI 应意识到命令会动选中，或在命令不声明 selection 时它不会动（见 CommandManager.undo 注释）。
6. **读取状态**：`editor.scenes.getActiveScene().tracks`（正式）或 `timeline.getPreviewTracks()`（含草稿）；`resolveAnimationPathValueAtTime` 可算任意时刻属性值，AI 可用来"读取当前画面语义"。

## 附录 B：十大架构事实（TL;DR）

1. **EditorCore 单例**持有 12 个 Manager，是唯一事实来源；React 靠 `useSyncExternalStore` 订阅。
2. **一切可撤销编辑 = 一个自包含 Command**（execute 保存 savedState，undo 整轨还原）。
3. **草稿层 previewOverlay** 让拖动有画面反馈又不污染历史，提交时折叠成 `TracksSnapshotCommand` push 入栈。
4. **另一条交互路径**（时间线移动/关键帧拖动）只用 session 算、松手提交语义命令，不碰草稿层。
5. **动画是 Binding+Channel 双层**：绑定管读法、通道管关键帧；缓动（贝塞尔）是 keyframe 的原生字段。
6. **属性路径统一解析**（`resolveAnimationTarget`）：内建属性/图形参数/特效参数走同一套动画读写。
7. **时间 = 整数 tick 的品牌类型 MediaTime**，帧率用 `{numerator, denominator}`，一切取整在 wasm 边界。
8. **渲染两阶段**：buildScene 建节点树（状态变化时重建）+ rAF 按帧号渲染（帧去重），Canvas 2D 与 GPU 双后端。
9. **保存是防抖订阅**：SaveManager 听 scenes+timeline，800ms 后写 IndexedDB/OPFS，版本化迁移 v0→v28。
10. **Manager 层就是 AI API**：所有编辑动作有命名命令/方法入口；仅视口缩放、吸附指示、面板布局等展示态硬编码于 UI。
