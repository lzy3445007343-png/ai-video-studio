## 〇、结论摘要（先看这个）

**方向全对，细节拧反**：

| 维度 | 判断 |
|---|---|
| 拖素材自动打 KF | ✅ 我们做对了（新版就是这么干）——之前拿旧版说"该删"是错的 |
| pointerdown 锁时间（X/Y 共用） | ✅ 我们 KET 已对齐（EditContext） |
| 拖 marker 只改 t 不改 v | ✅ 设计意图对齐（value:null） |
| **数据模型** | ❌ 我们是扁平 keys 数组，新版是 bindings+channels 双层（带 Bezier/切线/外推） |
| **容差哲学** | ❌ 我们用 ±1ms 合并 + ±1帧 对齐"修补"，新版用**严格相等**从根上避免 |
| **marker 视觉拖动** | ❌ 我们直接改 DOM style，新版纯函数计算 |
| **可动画属性** | ⚠️ 我们 6+1 通道，新版 14 路径（含 color/背景） |

**核心教训**：新版靠"**时间精确、绝不猜测**"（严格相等 + pointerdown 快照）避免一切错位；我们用"±容差 + 跨通道对齐"去**修补**错位——修补方向本身在制造新问题。对齐 = 换成新版的"精确"哲学。

## 一、数据模型对比

| 项 | 我们 | 新版 OpenCut | 影响 |
|---|---|---|---|
| **组织** | `seg.animations[path] = {keys:[...]}`（扁平，path 直接挂 keys） | `animations.bindings[path]`（定义属性 kind/components）+ `animations.channels[channelId]`（存 keys）**双层** | 新版支持"一个属性多个分量通道"（vector2/color），我们只能 1 属性=1 通道 |
| **关键帧结构** | `{id, t, v, seg}` | `{id, time, value, leftHandle?, rightHandle?, segmentToNext, tangentMode}` | 新版内置 **Bezier 手柄 + 切线模式**；我们只有 linear/hold |
| **插值** | linear / hold | linear / hold / **bezier**（带手柄） | GPT 早说过"B8 Bezier 是核心不是增强"，新版印证 |
| **外推** | 无 | `extrapolation.before/after`（KF 前后延伸模式：hold/linear） | 新版"最后一个 KF 之后怎么走"是显式定义 |
| **可动画属性** | 6 通道：positionX/Y、scaleX/Y、rotate、opacity（+后端 volume 未接通） | **14 路径**：positionX/Y、scaleX/Y、rotate、opacity、volume、color、background.paddingX/Y、offsetX/Y、cornerRadius | 新版覆盖面广（文字/背景都可动画） |
| **属性分组** | 无 | `transform.scale` = [scaleX, scaleY] 联动组 | 新版改 scaleX 可联动 scaleY（锁比例） |
| **时间单位** | t 微秒整数 | MediaTime（ticks 微秒）+ 显式 TICKS_PER_SECOND | 一致 ✅ |

## 二、行为层对比（逐项）

### 1. 拖预览素材 → 打 KF

| 环节 | 我们 | 新版 |
|---|---|---|
| 触发条件 | `hasAnimX \|\| hasAnimY`（任一通道开 KF 才打） | 同（`hasAnimatedPositionX/Y` 分别判断）✅ |
| 打点命令 | `add_keyframe(X, localSnap, nx)` + `add_keyframe(Y, localSnap, ny)` | `upsertElementKeyframe(X, localTime, position.x)` + (Y) ✅ |
| 打点时间 | EditContext 锁定的 `localUs`（pointerdown 快照） | `snapshot.localTime`（pointerdown 快照）✅ 一致 |
| 无动画通道 | 写静态 transform（update_segment_transform） | 写静态 transform（updates.transform）✅ 一致 |
| **同点已有 KF** | **±1ms 内 → 合并更新 v** ⚠️ | **严格相等才更新 v**（isNearlySameTime：`leftTime === rightTime`） | **差异根因①**：我们拖素材落在已有 KF 附近会误改 v |

### 2. 打点时间匹配（容差）

| | 我们 | 新版 |
|---|---|---|
| 新增/更新判定 | `abs(k.t - t) <= 1000`（±1ms）⚠️ | `leftTime === rightTime`（严格相等） |
| 跨通道对齐 | B3.4 曾加 ±1帧 对齐，**已禁用** ✅ | 无（不存在此概念） |
| 渲染合并 marker | `Math.abs(kt - t) <= 33333`（±1帧）⚠️ | 按 `Map<time, keyframes[]>` **同时间精确合并** |

**差异根因②**：我们用 ±容差在"时间不准"的前提下强行合并，导致 X/Y 微差被合并/拆散的不可预期行为；新版打点时间本身精确（pointerdown 快照 + 整数 ticks），严格相等即可正确合并。

### 3. 拖 marker 改时间

| | 我们 | 新版 |
|---|---|---|
| 拖动目标 | `collectSelKf` 从 `_selKf` Set 收集（含 path/kid/t） | `keyframeRefs` 快照（含 trackId/elementId/propertyPath/keyframeId）✅ |
| 提交命令 | `update_keyframe(value:null, time_us)` | `RetimeKeyframeCommand(nextTime)`——内部只调 `retimeElementKeyframe` 改 t ✅ |
| 一次 undo | withTx 批量 | `BatchCommand` 包全部 ✅ |
| **拖动中视觉** | **直接改 `m.style.left = ...`** ⚠️ | **`getVisualOffsetPx` 纯函数计算**（indicatorTime + deltaTicks → px，由渲染层重绘） | **差异根因③**：我们改 DOM，时间轴重建/引用变化 → "复制感/原地残留/弹回" |

### 4. 选择模型

| | 我们 | 新版 |
|---|---|---|
| 选择键 | `path|kid`（Set，同段假设） | `trackId:elementId:propertyPath:keyframeId`（全局唯一）⚠️ |
| 点选语义 | 未选中+无修饰→单选；Shift/Ctrl 增选；已选中→保持 | `toggleKeyframeSelection`：无修饰→单选；多键→toggle（已选则移除）✅ 基本一致 |
| 框选 | 未做（计划第二阶段） | `selectKeyframeRange`（anchor + range）❌ 缺失 |

### 5. 同点合并渲染（marker）

| | 我们 | 新版 |
|---|---|---|
| 合并粒度 | 按 t ±1帧 分组合并 → data-kids/paths | Map<time, keyframes[]>（同时间精确合并）✅ 思路一致，容差不同 |
| marker 结构 | `data-kids` / `data-paths`（逗号分隔） | `KeyframeIndicator.keyframes` 数组 ✅ |

### 6. 帧吸附

| | 我们 | 新版 |
|---|---|---|
| 拖 marker 吸附 | `Math.round(us/33333)*33333`（30fps 手写）⚠️ | `roundFrameTicks({ticks, fps})`（统一函数，fps 来自项目设置） |
| 播放头 seek 吸附 | `snapSeekMediaTime`（我们自己写了一套） | `snapSeekMediaTime`（wasm）✅ 概念一致 |

### 7. undo / 事务

| | 我们 | 新版 |
|---|---|---|
| 一次手势=一条 undo | withTx 批量（C3）✅ | BatchCommand ✅ |
| 拖素材=一条 | withTx drag-transform-kf ✅ | 隐式（preview commit）✅ |

### ✅ 已对齐（不用动）
1. 拖素材自动打 KF（方向正确）
2. pointerdown 锁时间（KET EditContext）
3. 拖 marker 只改 t 不改 v（value:null）

### ⚠️ 要改（差异根因）

## 四、差异根因分析（为什么我们"修补"方向反了）

我们一路遇到的问题（X/Y 错位、v 被改、复制感），**根因不是"缺功能"，而是"时间基准不精确 + 用容差修补"**：

```
我们：打点时间（浮点 playheadUs → int 截断，可能微差）
  → X/Y 微差 → 两个 marker → 拖只动一个 → "复制感"
  → 加 ±1ms 合并 → 误改 v → "拖素材改数值"
  → 加 ±1帧 跨通道对齐 → 掩盖真实错位 → 越修越乱

新版：打点时间 = pointerdown 锁定的精确 localTime（整数 ticks）
  → X/Y 严格同点 → 一个 marker → 拖=整组动，天然无错位
  → upsert 严格相等 → 只有真同点才更新 v，绝不误改
```

**对齐的本质：不是抄功能，是把"时间精确、绝不猜测"的哲学换成我们的。**
