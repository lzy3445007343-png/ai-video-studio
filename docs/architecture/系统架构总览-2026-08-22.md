# 系统架构总览（我们 vs 新版 OpenCut）——全景对比基准

> 日期：2026-08-22 21:40 · 系统级全景对比第 1 步
> 基准：新版 OpenCut `opencut-app/opencut` commit `0d354993`（85.4k★，opencut.app 线上同源）
> 定位：**先建双方系统地图，再逐层对比**——为后续大重构提供完整诊断视角。本文档不是"修 bug 方案"，是"重构前的全貌图"。

---

## 一、新版 OpenCut 系统地图（7 层）

```
① 触发层 Actions        actions/definitions.ts（注册表）+ useEditorActions（handler 绑定）
      │  快捷键 / UI 按钮 / 右键菜单 → 统一走 action
      ↓
② 业务层 EditorCore     core/index.ts（单例）：12 个 Manager 组合
      │  timeline/command/playback/scenes/project/media/renderer/save/audio/selection/clipboard/diagnostics
      ↓
③ 命令层 Commands      commands/*.ts：Command 抽象类 { execute(); undo(); redo() }
      │  BatchCommand 组合多命令 = 一条 undo；命令按域分文件（media/project/scene/timeline/element/keyframes/masks）
      ↓
④ 状态层 Stores        stores/*.ts（zustand）：keybindings 等 UI 状态；业务状态在 Manager/Scene 内
      ↓
⑤ 数据模型             TScene { id, tracks: {overlay[], main, audio[]}, bookmarks }
      │  TrackType: video/text/audio/graphic/effect（5 种轨）
      │  ElementRef { trackId, elementId } —— 用 id 引用，不依赖位置
      │  BaseTimelineElement { id, name, duration, startTime, trimStart, trimEnd, sourceDuration?, animations? }
      │  VideoElement { mediaId, transform: Transform, opacity, blendMode?, effects?, masks?, retime? }
      │  animations: ElementAnimations { channels: Record<path, AnimationChannel> }（bindings+channels 双层）
      ↓
⑥ 渲染层 Renderer      services/renderer/（GPU/WASM 合成，rust/crates）+ effects/masks 注册表
      ↓
⑦ 媒体层 Media         media-manager：IndexedDB 存媒体 + Blob URL（不复制文件）+ mediabunny(WASM) 异步探测
```

**关键特征**：
- 单例 EditorCore，Manager 显式方法调用，**无全局轮询**（SaveManager 是保存节流，不是状态轮询）
- 命令对象模式：每个操作一个类，自带 undo/redo
- 时间统一 MediaTime（120,000 ticks/s 整数）
- 渲染 GPU 合成（rust），组件级 DOM 复用（不重建）

## 二、我们的系统地图（7 层）

```
① 触发层               keydown 监听（HTML:3162）+ 按钮 addEventListener + 少量上下文
      │  散落绑定，无统一注册表
      ↓
② 状态层 Store         store.js：唯一真相源 Store.state + subscribeSlice 切片订阅 + _emit 全量
      │  + 500ms 轮询 refresh()（人/AI 实时互看）
      ↓
③ 内核层 Kernels       property/*.js：C1 Property Kernel / C2 Interaction Kernel / C3 CommandService
      │  C4 Subscription / C5 Canvas Coordinate / KET EditContext
      ↓
④ 命令层 CommandService property/command.js：run(cmdId,args) → call("execute") → Python 后端分发
      │  命令实际实现全部在 Python（main.py 90+ API 方法），前端只有 cmdId 字符串
      ↓
⑤ 数据模型             draft { main:{segs[]}, overlay:[], audio:[], text:[], canvas }
      │  seg { id, type, path/material_id, start, duration, src_start, src_end, src_full, speed,
      │        volume, transform:{x,y,scaleX,scaleY,rotation,opacity}, animations:{path:{keys:[{id,t,v,seg}]}},
      │        effects, masks }
      │  定位用 "type:ti:idx" 字符串（轨类型+轨索引+段索引）
      ↓
⑥ 渲染层 Renderer      renderer.js + timeline.js（DOM innerHTML 全量重建）+ player.js/media.js
      │  （CPU DOM 渲染）
      ↓
⑦ 媒体层 Media         assets/ 复制文件 + ffmpeg/ffprobe 同步探测 + draft_state.json 落盘
```

**关键特征**：
- 命令在**后端**（Python），前端薄壳——AI Agent 友好（MCP 直连）
- Store 全量订阅 + 500ms 轮询 = 双跑（已确认）
- 段定位用位置索引字符串（type:ti:idx）——**移动/删除后索引漂移**（曾有防漂移补丁）
- 时间 float 微秒

## 三、逐层对比表（差异即重构候选）

| 层 | 新版 OpenCut | 我们 | 差异性质 | 重构影响 |
|---|---|---|---|---|
| **触发层** | Actions 注册表统一 | 散落 keydown/按钮 | 结构差异 | 中（可渐进收口） |
| **状态层** | Manager 显式方法 + 无轮询 | Store 全量订阅 + 500ms 轮询 | **结构性差异** | **高（轮询是性能雷根）** |
| **命令层** | 前端 Command 类（自带 undo/redo） | 后端 Python 命令（前端薄壳） | 设计差异 | 中（我们这层是 AI 优势，**保留**） |
| **数据模型** | Scene→Track→Element（id 引用）+ transform 对象 + mediaId | draft→segs（type:ti:idx 位置引用）+ transform + path | **结构性差异** | **高（位置引用是漂移根）** |
| **动画模型** | bindings+channels 双层 + Bezier/tangent/外推 | 扁平 animations[path].keys | 结构性差异 | 高（X/Y 错位模型根） |
| **渲染** | GPU/WASM + DOM 复用 | CPU DOM 全量重建 | **架构级差异** | 极高（后置，大工程） |
| **媒体** | IndexedDB + Blob URL + WASM 异步 | assets 复制 + ffmpeg 同步 | 结构性差异 | 高（同步阻塞是卡死根） |
| **时间** | MediaTime 整数 tick | float 微秒 + 帧吸附补 | 结构性差异 | 高（浮点误差根） |
| **轨道** | 5 类型（video/text/audio/graphic/effect）| 4+1 类（main/overlay/audio/text/effect）| 相似 | 低 |
| **场景** | TScene 多场景 + bookmarks | 单 draft + bookmarks | 相似 | 低 |

## 四、核心结论（重构要点排序）

**1. 我们独有的优势（必须保留，重构时不能丢）**：
- 后端命令 + MCP（AI Agent 层，新版只是 README 未来方向）
- 剪映草稿导出（生态）
- 本地 Whisper 字幕

**2. 结构性债务（重构重点，按影响排序）**：
| # | 债务 | 后果（已见/潜在） | 重构方向 |
|---|---|---|---|
| D1 | **位置索引引用（type:ti:idx）** | 删除/移动后索引漂移 → 各种"找不到段" | 改 id 引用（对齐 ElementRef） |
| D2 | **500ms 轮询 + 全量重建** | 性能雷 + 素材库消失环境 | 事件驱动或增量渲染 |
| D3 | **float 微秒** | 浮点误差 → 帧不对齐 | MediaTime 整数化（渐进） |
| D4 | **扁平 keys 动画模型** | X/Y 天然可错位 | bindings+channels（或 PropertyGroup 折中） |
| D5 | **同步 ffmpeg** | 导入卡死 | 异步/后台线程 |
| D6 | **DOM 全量重建** | UI 跟手差 | 组件级复用（渐进） |

**3. 补丁债（A/B/C 三分法初判）**：
- A 类（错误补丁，可删）：±1ms 合并（已改严格相等）、跨通道对齐（已禁用）——**历史遗留代码待清理**
- B 类（兼容保护，留）：clamp/防 NaN/FIX-2 stale key 防御
- C 类（产品增强，留）：CommandService/EditContext/audit_log/MCP

## 五、下一步（逐子系统深审）
