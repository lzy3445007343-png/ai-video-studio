## OpenCut 三件事的本质

不是"处理了风险"，而是**让风险根本不存在**：

1. **一份真相源** —— 属性只有 `animations`（`bindings` 映射 `propertyPath`→`channelId` + `channels` 存关键帧），静态值只是兜底。
2. **一条解析链** —— 预览和导出共用同一个 resolver（`lib/animation/resolve.ts` + `services/renderer/resolve.ts`），没有"预览一套 / 导出另一套"。
3. **输入即吸附** —— 所有时间输入在落库前调 WASM `roundToFrame` 吸附到帧格，再**严格相等**比较，零容差。

## 风险 1：双真源（对应咱 5b）

| | 内容 |
|---|---|
| **OpenCut 做法** | 只有一份 `animations` 真相源。`resolve.ts:40 resolveTransformAtTime` 读 `transform.positionX` 等路径，`baseTransform` 只是"无动画时的兜底值"（`resolve.ts:141`：找不到 `bindings[path]` 就返回 fallback）。**没有任何 `params` + `transform` 双写**。 |

| **落实状态** | ⚠️ HELD：有 data-loss 风险，需两 commit 顺序 + 独立 revert，待用户拍板权威写者后做。 |

## 风险 2：特效 KF 预览≠导出（对应咱 5c）

| | 内容 |
|---|---|
| **OpenCut 做法** | 特效参数也做成 `animations` 里的路径 `effects.{effectId}.params.{paramKey}`（`effect-param-channel.ts:20 buildEffectParamPath`），用**同一个** `resolveEffectParamsAtTime`→`resolveAnimationPathValueAtTime` 解析。预览与导出共用 `services/renderer/resolve.ts` 这一条解析链（video/image/text/sticker/graphic 所有节点 + `:439 EffectLayerNode` 都走它）；导出=逐帧调同一 resolve 再 composite（`compositor/wasm-compositor.ts:123 renderFrame`）。**没有 css adapter vs ffmpeg adapter 两套**。 |
| **咱现状（反模式）** | `effects.js:11` 明写 css adapter=预览、ffmpeg adapter=导出；导出是静态的 → 特效参数动画"预览动、导出静"。 |
| **借鉴方案** | 把特效参数关键帧也存进 `seg["animations"]`（路径 `effects.{id}.params.{key}`），导出复用 `_apply_keyframes_to_segment`（现已处理变换，扩展到特效参数）→ 预览=导出。 |
| **落实状态** | ⚠️ HELD：需定处置策略（显式声明差异 / 导出降级映射 / 并入统一 channel），待用户拍板。 |
